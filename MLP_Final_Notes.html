Welcome! We will build a model the way we might teach a helper to make a decision: show examples, let it find patterns, and then check whether it can handle examples it has never seen.

This notebook sets up the words and workflow used in every later notebook.

The five words we will use constantly

  • Example / sample / row: one thing we measured, such as one house or one passenger.
  • Feature / input / column: a measured clue about an example, such as house size.
  • Target / label: the answer we want the computer to learn to predict, such as house price.
  • Model / estimator: the learning recipe. In scikit-learn, we create it, call .fit(...), and then ask it to .predict(...).
  • Training: finding model settings from examples and their answers.

A spreadsheet of house examples may have columns size, bedrooms, and price. Here, the first two are features X; price is target y. The capital X is a common convention for a two-dimensional feature table.

The standard scikit-learn recipe

  1. Prepare a feature table X and target y.
  2. Split examples into training and test sets.
  3. Create an estimator with its chosen settings (called hyperparameters).
  4. Call .fit(X_train, y_train) to learn from training examples.
  5. Call .predict(X_test) to predict answers for held-out examples.
  6. Compare predictions with real test answers using a metric.

We keep the test examples away from training so the test score is a fairer rehearsal for new, unseen data. Later notebooks explain how to avoid accidentally leaking information from test data.

What every line is doing

  • load_iris(return_X_y=True) gives us numeric measurements and flower-class labels.
  • X.shape is (150, 4): 150 rows and 4 feature columns. y.shape is (150,): one answer for each row.

A score is not a promise about every future example. It is evidence from this particular held-out sample.

A few rules that protect your result

  • Never train on the test answers.
  • Learn scaling, imputation, or feature-selection settings from training data only.
  • Use a pipeline when you need preprocessing plus a model; it helps apply the steps correctly in cross-validation.
  • Always check the shape of your data. Most scikit-learn features are arranged as rows = examples and columns = features.
  • A high training score alone does not show that a model generalizes. Compare held-out performance too.

0302 · Train/test splitting, sampling, and leakageReady

02 · Train/test splitting, sampling, and leakage

Imagine practicing for a spelling test. If you memorize the exact questions that will be graded, your score does not tell us whether you learned the spelling rules. A test set works like questions kept aside until the end.

Why split?

The training set is for learning model parameters. The test set is held out to estimate performance on new examples. Typical splits might reserve 20–30% for testing, but the best fraction depends on how much data you have and how the model will be used.

The training and test samples should represent the same real-world population. If training contains only small homes and testing only mansions, the score mixes model quality with a distribution shift.

Python · code cell 1
Click Run to execute this cell.

Understand the arguments

  • test_size: if a decimal, it is the test fraction; if an integer, it is a test-row count.
  • train_size: optionally specifies the training fraction/count.
  • random_state: fixes the random shuffle so repeated runs produce the same split.
  • shuffle: shuffles before splitting (default is True).
  • stratify=y: keeps class proportions similar across splits, useful for classification.

The split does not magically make data representative. You need to choose a sampling method suitable for how data was collected.

The scaling leakage trap

A scaler estimates information such as means and standard deviations. If we fit it using all rows before splitting, the test set influenced training-time preprocessing. That is a small form of data leakage. Fit the scaler on training data, and use those learned values to transform test data.

Python · code cell 2
Click Run to execute this cell.

Other examples of leakage

Leakage can happen if you use test labels to choose features, fill missing values using whole-dataset averages, tune settings repeatedly against the test score, or accidentally leave the target column inside X. The test set should be used for the final check, not as a coach while you are choosing the model.

A pipeline (Notebook 03 and 09) makes it easier to fit preprocessing correctly inside each training split.

Random vs stratified sampling

A random split samples rows without deliberately preserving class counts. With a rare class, chance may leave too few examples in one split. Stratification attempts to preserve class proportions. Stratification is not appropriate for every task (for example, some time-ordered forecasting); the split should reflect the real deployment situation.

Scaling numeric features

  • StandardScaler subtracts a feature mean and divides by its standard deviation. The result is centered near 0 with standard deviation near 1.
  • MinMaxScaler maps values to a chosen interval, often 0 to 1.
  • Normalizer rescales each row (sample) to a unit norm. This is different: it operates across the features of each row, not across rows per feature.

Scaling is important for distance-based models, SVMs, and many optimization methods. Tree splits are usually not sensitive to monotonic scaling.

0504 · Choose useful clues and compress featuresReady

04 · Choose useful clues and compress features

A dataset might have many columns, some helpful and some noisy. Feature selection tries to keep useful original columns. PCA makes a smaller set of new columns that combine information from the originals.

Filter methods: score each feature

A filter method scores features using a statistic, without repeatedly training a full predictive model. VarianceThreshold removes features that hardly change. SelectKBest keeps the k best scores using a scoring function suited to the task. For regression, f_regression is a common linear association score; for classification, use a classification score such as f_classif.

Python · code cell 1
Click Run to execute this cell.

Why fit selection on training rows only?

Feature selection looks at values and often at target labels. If it examines test rows or labels, it has already learned something about the final exam. Split first; fit the selector on training data; transform both training and test data with that selector. Put it inside a pipeline when using cross-validation.

Wrapper methods: RFE

Recursive Feature Elimination (RFE) trains an estimator, ranks feature importance, removes the least important feature(s), and repeats until the requested number remains. This can model interactions with a particular estimator better than simple univariate scoring, but costs more computation because it fits repeatedly.

Python · code cell 2
Click Run to execute this cell.

PCA: create new combined features

Principal Component Analysis finds directions through the data along which values vary the most. It rotates the coordinate system and can keep only the first few directions. These new columns are principal components; they are combinations of original features, not selected original columns.

PCA is sensitive to scale, so standardize numeric features first. Fit PCA on training data only. A component with greater explained variance captures more of the data's variation, but variance is not necessarily the same thing as usefulness for predicting y.

Keep the two ideas separate

  • Feature selection: keep/drop the original columns; easier to explain which measured clues were used.
  • PCA: replace originals with components; useful for compression or correlated numeric features, but harder to explain in original units.
  • Both can be part of a pipeline and must be fitted using training data only.

0605 · Predict numbers: regression and regularizationReady

05 · Predict numbers: regression and regularization

Regression predicts a number, like price, height, or tomorrow’s temperature. We will start with a line, then allow curves, and finally learn how regularization can keep a model from becoming too wiggly.

Linear regression: a weighted recipe

For one feature, the prediction is ŷ = w x + b. w is the coefficient (slope); b is the intercept. For several features, add their weighted contributions: ŷ = w₁x₁ + w₂x₂ + ... + b. The model chooses coefficients that minimize the sum of squared residuals, where a residual is actual − predicted.

This is linear in the parameters. The model can still use transformed inputs such as x², which lets it trace a curve.

Python · code cell 1
Click Run to execute this cell.

What does fit_intercept mean?

With fit_intercept=True, the model learns b. With False, it forces b=0 and the line through the origin. Use the forced-origin version only when the problem or domain supports that assumption; otherwise it can distort the slope.

Regression scores: MAE, MSE, RMSE, R²

  • MAE: average absolute error; in the same units as y.
  • MSE: average squared error; larger mistakes get extra weight and units are squared.
  • RMSE: square root of MSE; returns to y's units.
  • R²: compares squared prediction error with a baseline that predicts the target mean. 1 is perfect; 0 is baseline-like; it can be negative when the model is worse than that baseline.

For MAE/MSE/RMSE, lower is better. For R², higher is usually better.

A straight line may be too simple for curved patterns. PolynomialFeatures expands x into extra columns, such as [x, x², x³]. LinearRegression then finds a weighted sum of these columns. The model remains linear in the learned coefficients, even though its curve is nonlinear in x. Degree 1 is a line; a high degree can overfit.

Regularization: discourage overly large coefficients

Ridge (L2) adds a penalty proportional to the sum of squared coefficients. Lasso (L1) adds a penalty proportional to the sum of absolute coefficients and may set some exactly to zero. These penalties discourage overly complicated fits. The setting alpha controls penalty strength: too large can underfit; too small may not reduce overfitting. 0706 · Predict categories: classification and metricsReady

06 · Predict categories: classification and metrics

Classification predicts a category, like spam/not spam or flower type. A classifier may give a class label, and some classifiers also give a probability for each class.

Logistic regression is a classifier

Despite “regression” in its name, logistic regression is commonly used for classification. For binary classification, it maps a weighted sum through a sigmoid so the value becomes a probability between 0 and 1. A threshold (commonly 0.5) turns that probability into a class. For multiclass tasks, scikit-learn supports multinomial logistic regression in appropriate configurations.

Click Run to execute this cell.

Confusion matrix and four counts

For binary labels, a confusion matrix compares true rows with predicted columns. It counts true positives (TP), false positives (FP), true negatives (TN), and false negatives (FN). Keep track of which label is considered positive; reversing that choice changes the meaning of precision and recall.

Python · code cell 2
Click Run to execute this cell.

Pick a metric that matches the cost of mistakes

  • Accuracy = correct predictions / all predictions. It can look impressive when one class is very common.
  • Precision = among predicted positives, how many were truly positive? Useful when false alarms are costly.
  • Recall = among actual positives, how many did we find? Useful when missing a positive is costly.
  • F1 is the harmonic mean of precision and recall. It is high only when both are reasonably high.

The default classifier .score(X, y) is usually accuracy. Never assume every .score value is the same metric; check the estimator documentation.

Regression and classification are different jobs

Regression outputs numeric quantities; classification outputs labels. Accuracy is for classification, not a regression loss. MAE and MSE are standard regression metrics. Conversely, R² is not a classification accuracy measure.

Bayes’ rule combines prior probability with how likely the evidence is under each class. Naive Bayes makes the simplifying assumption that features are conditionally independent given the class. K-nearest neighbours: ask the nearby examples

KNN stores training examples. To classify a new example, it finds the k nearest training examples and lets them vote. Distance measures such as Euclidean distance are affected by scale, so scaling features is important. A very small k can be noisy; a very large k can blur class boundaries. 08 · SVMs, decision trees, forests, and boosting

We will meet four model families. SVMs look for a wide separating margin; trees ask a sequence of questions; forests combine many trees; boosting builds learners in sequence.

Support Vector Machines

A linear SVM chooses a boundary that separates classes while maximizing the margin: the gap around the boundary. A kernel lets an SVM model curved boundaries by comparing examples in an implicit transformed space. Scaling is usually important. C controls the trade-off between a wider margin and fewer training errors; gamma influences how local an RBF-kernel boundary can be.

A decision tree asks feature questions such as “is petal width less than 0.8?” Each split tries to make child groups purer. Classification trees often use Gini impurity or entropy. 1009 · Evaluate fairly and tune model settingsReady

09 · Evaluate fairly and tune model settings

One train/test split can be lucky or unlucky. Cross-validation repeats training and validation on different folds. Hyperparameter search tries settings such as model depth or number of neighbours.

K-fold cross-validation

In k-fold CV, split training data into k parts (folds). Train on k−1 folds and score on the remaining fold. Repeat until every fold has been the validation fold, then average the scores. The held-out test set stays untouched until final evaluation. Cross-validation estimates performance more steadily than a single split, but it costs more model fits.

Leave-One-Out CV

With n samples, Leave-One-Out uses n folds: each round trains on n−1 examples and validates on the single remaining example. It can be expensive for large datasets. The number of scores returned equals the number of samples.

Grid search

A hyperparameter is a setting chosen before fitting, such as max_depth. GridSearchCV evaluates every combination in a specified grid using cross-validation. It selects the setting with the best mean CV score, then by default refits that best configuration on all data passed to .fit. Search only within training data; keep the final test set separate.

RandomizedSearchCV and scoring direction

RandomizedSearchCV samples a fixed number of parameter combinations from distributions/lists. It can explore large settings spaces with fewer fits than an exhaustive grid. Read best_score_, best_params_, and best_estimator_ after fitting.

Scikit-learn maximizes scores. For losses where lower is better, scorer names such as neg_mean_squared_error use negative values so larger scores correspond to lower error. To report ordinary MSE, change the sign back.

For regression, scikit-learn scorer names such as neg_mean_squared_error are negative so maximization still selects the smallest loss. For example, -25 is better than -100 because its underlying MSE (25) is smaller.

Why pipelines matter inside CV

If scaling is done once before CV, each validation fold can influence the scaler. Instead, put the scaler and estimator in a pipeline. During each fold, the pipeline learns the scaler from only that fold’s training rows. This also applies to imputation, encoding, feature selection, and PCA.

1110 · Neural networks with scikit-learnReady

10 · Neural networks with scikit-learn

A neural network connects simple units called neurons. Each neuron combines inputs with weights and a bias, then applies an activation function. Layers let the model build more complicated patterns from simpler ones. This notebook uses scikit-learn’s MLPClassifier and MLPRegressor.

One neuron, written as a formula

For inputs x and weights w, a neuron first calculates z = w·x + b (weighted sum plus bias). Then it calculates activation a = f(z). ReLU is max(0,z); sigmoid squashes values between 0 and 1. A network repeats this recipe across layers. In a layer with 5 neurons, each neuron has its own row of weights and its own bias.

How many parameters?

For a dense layer with n_in input values and n_out neurons, there are n_in × n_out weights and usually n_out biases. Total: n_in*n_out + n_out. A network’s parameter count is the sum for every dense layer. More parameters can model more patterns, but may need more data and regularization.

Training warnings and limits

An MLP may show a convergence warning when it reaches max_iter before its loss meets the stopping tolerance. Scaling, a different learning rate, more iterations, or simpler architecture may help. Do not silence warnings without understanding them. MLPClassifier is a teaching entry point; for deep learning research or GPU-scale networks, PyTorch or TensorFlow are more flexible.

These notes restate the API details most useful for the topics in the MLP notebooks. Use the linked official docs for complete signatures, version changes, estimators, and edge cases.

The estimator contract

Most scikit-learn estimators follow a shared pattern. Create an object with constructor settings (hyperparameters). fit(X, y) learns from samples and labels; predict(X) produces predictions; many classifiers also implement predict_proba(X). A transformer implements fit(X) and transform(X); fit_transform(X) combines these for training data. Learned values usually appear in attributes ending with _, such as coef_, mean_, categories_, and best_score_. Constructor values do not usually end in _. score(X,y) is estimator-specific: common defaults are R² for regressors and accuracy for classifiers.

X has shape (n_samples, n_features): rows are examples, columns are features. A one-dimensional target often has shape (n_samples,). Pass feature matrices as two-dimensional objects even when there is one feature.

Split and leakage details

train_test_split(*arrays, test_size=None, train_size=None, random_state=None, shuffle=True, stratify=None) splits arrays with matching first dimensions. A float test size is a proportion; an integer is a row count. A fixed integer random_state makes the pseudo-random split reproducible. stratify=y keeps class proportions approximately stable. Do not use a random shuffle for time-ordered data when future observations must not inform the past.

Fit any learned preprocessing—imputation, scaling, feature selection, PCA, encoding categories—on the training part only. Apply its .transform() to validation and test parts. A Pipeline enforces this correctly inside cross-validation: each fold fits the transformer on that fold's training rows. Pipeline parameter names use step_name__parameter_name, such as classifier__C.

Preprocessing reference

  • StandardScaler: for each feature, subtract the training mean and divide by the training standard deviation. A constant feature is handled safely. It is sensitive to outliers. Centering a sparse matrix would destroy sparsity, so use with_mean=False for sparse input.
  • MinMaxScaler: maps training extrema to a chosen range (default 0…1). Test values can fall outside that range if they exceed training extrema; the scaler does not make outliers disappear.
  • Normalizer: scales each sample/row to unit norm. It differs from standardizing each feature across samples.
  • SimpleImputer: learns a per-column replacement. mean and median require numerical data; most_frequent supports categorical-like data; constant uses fill_value. add_indicator=True appends missingness flags for columns that had missing entries when fitting. Check shapes and behavior for entirely empty columns against your installed version.
  • OneHotEncoder: learns categories from training data and creates binary indicator columns. By default, unknown categories at transform time raise an error; handle_unknown="ignore" emits all zeros for that encoded feature group. sparse_output controls sparse/dense output in current scikit-learn; older versions used the name sparse.
  • OrdinalEncoder: maps each input feature's categories to integers. Supply ordered category lists when order matters; integer codes imply order to many algorithms.
  • LabelEncoder: encodes target labels y, not nominal columns of X in the usual workflow.
  • ColumnTransformer: applies named transformers to selected columns and concatenates results. remainder="drop" is the default for unlisted columns; use remainder="passthrough" to keep them. Output can be sparse depending on constituent transformers and density.
  • Pipeline: every non-final step must transform; the final estimator needs fit. Calling pipeline .fit fits steps in order; .predict transforms then predicts. It supports cross-validation and parameter search as one estimator.

Feature selection and PCA details

A selector is a transformer, so put it in the pipeline after splitting. Univariate filter methods score a feature with a target association statistic; SelectKBest keeps exactly k columns, while SelectPercentile keeps a chosen percentage. Choose regression scoring functions for regression targets and classification functions for categorical targets. VarianceThreshold is unsupervised and removes low-variance columns. RFE repeatedly fits a supplied estimator and removes low-ranked features; its ranking is estimator-dependent. PCA centers data and finds orthogonal directions of high variance; feature scale matters, and components are new linear combinations rather than original columns. n_components=0.95 means retain enough components to explain the specified fraction of variance when using a compatible solver.

Regression and metrics details

LinearRegression(fit_intercept=True) minimizes residual sum of squares. It stores learned coefficients in coef_ and intercept in intercept_; with fit_intercept=False it constrains the intercept to zero. .score returns coefficient of determination R². R² can be negative on test data. MAE is mean absolute error; MSE averages squared error; RMSE is its square root. They have different units/sensitivity to outliers. For model selection, scikit-learn scorers use a “higher is better” convention, so losses may appear negated, such as neg_mean_squared_error.

PolynomialFeatures creates powers and interaction terms (depending on settings); feature count can grow quickly with degree. Ridge penalizes squared coefficient magnitude; Lasso penalizes absolute magnitude and can set coefficients to zero. Scale features before coefficient regularization. SGDRegressor learns with stochastic gradient updates; max_iter caps epochs, tol is a stopping tolerance, and learning-rate settings affect convergence.

Classification and model reference

  • Logistic regression is a classifier despite its name. predict gives class labels; predict_proba gives per-class probabilities when supported. classes_ states their column order.
  • Accuracy is fraction correct. Precision is TP/(TP+FP); recall is TP/(TP+FN); F1 is the harmonic mean of precision and recall. Confusion-matrix label order should be checked when interpreting cells. For imbalanced classes, accuracy alone may conceal poor minority-class performance.
  • Gaussian Naive Bayes estimates class-conditional Gaussian feature distributions and applies Bayes' rule under conditional independence assumptions.
  • KNN predicts from nearby training samples; n_neighbors, distance metric, and weights matter. Feature scaling is usually essential.
  • SVM C controls regularization/margin tradeoff; kernel and (for RBF) gamma affect boundary complexity. Scale features.
  • Decision trees split features to reduce impurity. max_depth, min_samples_split, and min_samples_leaf constrain complexity; trees are generally scale-insensitive.
  • Random forests average/vote across randomized trees; boosting adds learners sequentially. Ensembles can reduce variance or bias but still need held-out evaluation.
  • MLPClassifier/MLPRegressor use hidden layers; hidden_layer_sizes=(a,b) means two hidden layers of sizes a and b. Scale inputs. alpha controls L2 regularization; max_iter caps training iterations; a convergence warning means the stopping condition was not reached within the limit.

Validation and search details

cross_val_score(estimator, X, y, cv=..., scoring=...) returns one score per split. In K-fold CV, each fold is held out once. LeaveOneOut makes one sample the validation set per fold, resulting in n fits. Put preprocessing in a pipeline before cross-validation. GridSearchCV tries every parameter combination; RandomizedSearchCV samples a specified number. Both select by the mean validation score and by default refit the best estimator on all rows passed to their .fit. Keep the final test set outside parameter selection.
