1. From raw sequence to a model-ready batch

1.1 Tokenization, vocabulary, and special tokens

Start from zero: how does text become model input? A model does not receive a sentence as a human-readable idea. A tokenizer cuts it into pieces—whole words or word parts—and looks up an integer ID for each piece. For example, “unhelpful” might become “un”, “help”, and “ful.” Special tokens are extra markers that mean things like “start,” “separate,” or “padding.”

A text model does not consume words directly. A tokenizer maps text to token IDs. A vocabulary maps each known token to an integer; an embedding table maps each integer to a learned vector. A practical vocabulary reserves IDs for PAD (batch filler), UNK (unseen token), and often BOS/EOS (sequence boundaries).

text → tokenizer → integer IDs → embedding vectors → sequence model

Build the vocabulary from the training split only. If test text helps decide which tokens get a vocabulary entry, the test split has influenced training. Word-level tokenization is easy to inspect; subword tokenization handles rare words better but changes the meaning of vocabulary size and perplexity.

Important distinction: token IDs are category labels, not numeric measurements. ID 40 is not “twice” ID 20. The embedding layer learns a geometry; never feed arbitrary token IDs as continuous scalar features unless that is intentionally designed.

1.2 Padding and lengths

Sequences in a minibatch often have different lengths. Right-pad them to the batch maximum length so they form a rectangular tensor. Keep the true length for each row. Padding is not language and must not influence the summary state, pooled representation, or token loss.

from torch.nn.utils.rnn import pad_sequence
# seqs: list of integer tensors, e.g. [tensor([4, 8]), tensor([3, 2, 9])]
tokens = pad_sequence(seqs, batch_first=True, padding_value=PAD_ID)
lengths = torch.tensor([len(s) for s in seqs])
# tokens: [B, T_max]; lengths: [B]

For a dense padded batch, an attention mask is often tokens != PAD_ID. For an RNN, use packed sequences when appropriate or gather the output at lengths - 1. Simply selecting output[:, -1] is wrong if the last column is padding. In a bidirectional model, use the returned final states carefully: the reverse direction’s final state is not the same as the reverse component of the last output timestep.

2. Sentiment analysis with an LSTM

2.1 Many-to-one classification

For a review “the film was surprisingly good”, the model reads token vectors in order and updates state. The final valid state summarizes the prefix; a linear classifier maps it to two logits. The predicted class is argmax(logits). During training pass raw logits to CrossEntropyLoss and integer labels in {0,…,C−1}. Do not apply softmax before this loss.

IDs [B,T] → Embedding [B,T,E] → LSTM → hfinal [B,H] → Linear → logits [B,C]

For a one-layer unidirectional LSTM with batch_first=True, input is [B,T,E], output is [B,T,H], and each final state h_n/c_n has shape [1,B,H]. h_n[-1] gives [B,H]. This is the final recurrent state, not a softmax probability.

2.2 Worked parameter-count example

Suppose vocabulary size V=1,000, embedding width E=32, LSTM hidden width H=64, and C=2 classes. With a trainable embedding and PyTorch’s default two bias vectors per LSTM gate block:

  1. Embedding: V×E = 1,000×32 = 32,000.
  2. LSTM: 4H(E+H)+8H = 4×64×(32+64)+8×64 = 24,576+512 = 25,088.
  3. Linear head: H×C+C = 64×2+2 = 130.
  4. Total = 32,000+25,088+130 = 57,218 trainable parameters.

Why the 8H? Each of four gates has one input bias and one recurrent bias, each of width H. If the framework or a custom implementation combines biases, the formula may differ; state assumptions in an exam answer.

2.3 Small code: a shape-safe classifier

class SentimentLSTM(nn.Module):
    def __init__(self, vocab_size, emb_dim, hidden, classes, pad_id):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, emb_dim, padding_idx=pad_id)
        self.rnn = nn.LSTM(emb_dim, hidden, batch_first=True)
        self.head = nn.Linear(hidden, classes)

    def forward(self, token_ids, lengths):
        x = self.embedding(token_ids)          # [B,T,E]
        out, (h_n, c_n) = self.rnn(x)          # out [B,T,H]
        rows = torch.arange(x.size(0), device=x.device)
        last = out[rows, lengths - 1]          # [B,H], excludes right-padding
        return self.head(last)                 # [B,C] logits

padding_idx stops the padding embedding from being updated, but it does not itself prevent a recurrent layer from processing padded time steps. Gathering at each last valid index or packing is still necessary.

2.4 Evaluate the classifier

Accuracy can conceal class imbalance. Inspect the confusion matrix, precision, recall, and F1. For positive class: precision=TP/(TP+FP), recall=TP/(TP+FN), and F1=2PR/(P+R). Choose the positive label deliberately. Split by user/reviewer when repeated authors could leak style across train and test.

Exam answer pattern: First list input, recurrent output, and logits shapes. Then say the correct loss/label pairing. Finally point out whether padding, train/eval mode, or gradient reset is mishandled.

3. Character or word-level text generation

3.1 Shift the sequence by one token

Given a tokenized sequence [BOS, I, like, tea, EOS], the input is [BOS, I, like, tea] and the target is [I, like, tea, EOS]. At position t, the logits predict the next token. Training compares all positions against shifted targets, ignoring PAD targets with ignore_index.

3.2 Teacher forcing and inference are different

Why can generation be harder than training? During practice, teacher forcing gives the model the correct previous word each time, like practising a song while someone keeps the score in front of you. When generating, the model must use its own last word. One early wrong guess can send the next guesses off course; this gap is called exposure bias.

During teacher forcing, each next model input is the true previous token. During generation, the model feeds back its own sampled or selected token. This train/inference difference is called exposure bias. Generate autoregressively until EOS or a maximum length.

Greedy decoding chooses the highest-probability token each step and can be repetitive. Temperature τ rescales logits by z/τ before softmax: smaller τ sharpens the distribution; larger τ flattens it. Temperature is not a training parameter and does not guarantee a better sample. Top-k keeps only k highest scores; nucleus/top-p keeps the smallest probability-sorted set whose cumulative probability reaches p.

3.3 Numerical: next-token loss and perplexity

If the correct next token receives probability p=0.20, its negative log-likelihood is −ln(0.20)=1.609 nats. If four equally weighted target positions have probabilities .5, .25, .8, .4, then mean NLL = [−ln(.5)−ln(.25)−ln(.8)−ln(.4)]/4 = (0.693+1.386+0.223+0.916)/4 = 0.805. Perplexity=e0.805≈2.24. A perplexity near 2.24 means the model’s average uncertainty is comparable to choosing among about 2.24 equally likely options; it is not an accuracy percentage. Comparisons require the same dataset and tokenization.

3.4 Small code: shift and mask

# tokens is [B,T] with right padding and an EOS token
inputs = tokens[:, :-1]
targets = tokens[:, 1:]
logits = language_model(inputs)       # [B,T-1,V]
loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1),
    ignore_index=PAD_ID
)

Cross entropy internally applies log-softmax in a numerically stable way. Do not one-hot encode integer target IDs for CrossEntropyLoss. A comprehension/code-output question may ask what shape flattening creates: [B(T−1),V] logits and [B(T−1)] target IDs.

4. Time-series forecasting without leakage

Start from zero: what is data leakage? It is accidentally letting tomorrow’s information help predict yesterday. For forecasting, split data by time: train on the past, validate on a later period, and test on the latest period. Also calculate scaling averages using training data only. If future values influence preprocessing, the score looks better than a real future forecast would be.

4.1 A sliding-window dataset

For a one-step univariate forecast with window L, each example maps the previous L observations to the next value: [yt−L+1,…,yt] → yt+1. For F known features, input shape is [B,L,F]; target can be [B,1] or [B,H] for horizon H. Multi-step forecasting must state whether it predicts one point, a whole horizon, or feeds its own predictions back recursively.

def make_windows(series, lookback):
    X, y = [], []
    for end in range(lookback, len(series)):
        X.append(series[end-lookback:end])
        y.append(series[end])
    return np.asarray(X), np.asarray(y)

4.2 Chronological split and fit preprocessing only on train

Never randomly shuffle time points before splitting: future information can leak into training. Split the raw timeline first (for example, earliest 70% train, next 15% validation, newest 15% test). Fit mean/standard deviation on the train period only and transform all later periods using those train statistics. For a validation target immediately after the training boundary, its input window may contain earlier training observations because those observations would be known at prediction time; however no target or fitted statistic from the future may enter training.

Leakage traps: random splitting a time series; scaling using the full-series mean; using a feature whose future value is not actually available; allowing overlapping windows with future targets to cross the split; selecting a forecast horizon after seeing test results.

4.3 Metrics: MAE and RMSE

For truth [10,12,14] and prediction [11,10,15], errors are [1,−2,1]. MAE=(|1|+|−2|+|1|)/3=4/3≈1.333. MSE=(1+4+1)/3=2. RMSE=√2≈1.414. MAE is in target units and is less sensitive to a large outlier; RMSE is also in target units but penalizes large errors more strongly. Always compare with a naive baseline such as persistence ŷt+1=yt or seasonal-naive forecasting.

4.4 Rolling-origin evaluation

For a time series, train through time t, forecast t+1…t+H, advance the origin, and repeat. Report metrics by horizon: a model can be good at one step and poor at longer horizons. Recursive forecasts accumulate error; direct models predict each horizon directly; sequence-to-sequence models emit an entire horizon. Choose based on data size, horizon, and deployment constraints.

5. Worked numericals and code-reading patterns

Numerical A: LSTM batch shapes

Let B=16, T=25, E=40, H=64, C=3, one direction, one layer, and batch_first=True. Token IDs [16,25]; embedding [16,25,40]; LSTM output [16,25,64]; final h and c [1,16,64]; remove layer axis to [16,64]; classifier logits [16,3]. The integer labels must be [16].

Numerical B: embedding + recurrent parameters

V=2,000, E=32, H=48, C=2: embedding=64,000; LSTM=4H(E+H)+8H=4×48×80+384=15,744; classifier=48×2+2=98; total=79,842. This assumes the default two bias vectors per PyTorch LSTM layer and a trainable embedding.

Numerical C: Perplexity from one token

Target probability .1 gives NLL=−ln(.1)=2.302585 nats. For a single token, perplexity=eNLL=10. For a sequence, exponentiate the mean token NLL, not the sum.

6. Exam-pattern practice with worked answers

Q1. A batch has 8 padded token sequences of width 12; embedding width 20. What are the token, embedding, and one-direction LSTM output shapes if H=32 and batch_first=True?

Token IDs [8,12]; embedding [8,12,20]; LSTM output [8,12,32]. With one layer/direction, h_n and c_n are [1,8,32]. If the true lengths differ, the final representation must select each row’s last real timestep.

Q2. Which LSTM gate controls how much of the old cell state is retained?

The forget gate: ct=ft⊙ct−1+it⊙gt. Since f is sigmoid-valued in [0,1], a component near 1 preserves that component of memory, while a component near 0 removes it. The gate is not a class probability.

Q3. If one target token has p=.1, compute NLL and single-token perplexity.

NLL=−ln(.1)=2.3026 nats; perplexity=exp(2.3026)=10.

Q4. A validation loss is computed after training. Which operations should be absent?

No backward pass and no optimizer update. Set model.eval() (dropout/BatchNorm behavior) and use torch.no_grad() or inference mode (autograd graph). These controls solve different problems.

Q5. A forecast has true values [4,6] and predictions [5,3]. Find MAE and RMSE.

Errors [1,−3]; MAE=(1+3)/2=2. MSE=(1+9)/2=5; RMSE=√5≈2.236 in target units.

7. One complete end-of-week program: sentiment, generation, and forecasting

This CPU-friendly lab creates small synthetic datasets so the entire workflow is inspectable without downloading a corpus. It trains (1) an LSTM sentiment classifier from variable-length token sequences, (2) a GRU character-level next-token model with autoregressive sampling, and (3) an LSTM one-step forecaster on a chronologically split synthetic signal. The tiny data is for learning code flow, not for claiming useful model quality.

"""Week 6 lab: three sequence tasks in one small PyTorch program."""
import math
import random
import numpy as np
import torch
from torch import nn
from torch.nn import functional as F
from torch.nn.utils.rnn import pad_sequence
from torch.utils.data import DataLoader, TensorDataset

SEED = 7
random.seed(SEED); np.random.seed(SEED); torch.manual_seed(SEED)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# ------------------------------------------------------------
# A. SENTIMENT: right-padded token IDs -> two class logits
# ------------------------------------------------------------
PAD, UNK = 0, 1
positive = ["good", "bright", "love", "great", "warm"]
negative = ["bad", "dull", "hate", "awful", "cold"]
neutral = ["movie", "story", "was", "quite", "really", "the"]

# Deterministic toy reviews. Real work: replace with a real labeled corpus.
reviews, labels = [], []
for _ in range(40):
    reviews.append([random.choice(neutral), random.choice(positive),
                    random.choice(neutral)])
    labels.append(1)
    reviews.append([random.choice(neutral), random.choice(negative)])
    labels.append(0)
vocab_words = sorted(set(positive + negative + neutral))
word_to_id = {word: i + 2 for i, word in enumerate(vocab_words)}
vocab_size = len(word_to_id) + 2
encoded = [torch.tensor([word_to_id[w] for w in r], dtype=torch.long)
           for r in reviews]
lengths = torch.tensor([len(r) for r in encoded], dtype=torch.long)
tokens = pad_sequence(encoded, batch_first=True, padding_value=PAD)
labels = torch.tensor(labels, dtype=torch.long)

# Hold out a deterministic tail, and do not tune based on the final test set.
cut = int(0.8 * len(labels))
train_ds = TensorDataset(tokens[:cut], lengths[:cut], labels[:cut])
valid_ds = TensorDataset(tokens[cut:], lengths[cut:], labels[cut:])
train_loader = DataLoader(train_ds, batch_size=16, shuffle=True)
valid_loader = DataLoader(valid_ds, batch_size=16, shuffle=False)

class SentimentModel(nn.Module):
    def __init__(self, vocab, emb=16, hidden=24):
        super().__init__()
        self.embedding = nn.Embedding(vocab, emb, padding_idx=PAD)
        self.lstm = nn.LSTM(emb, hidden, batch_first=True)
        self.classifier = nn.Linear(hidden, 2)

    def forward(self, ids, lens):
        x = self.embedding(ids)                 # [B,T,E]
        out, _ = self.lstm(x)                  # [B,T,H]
        row = torch.arange(ids.size(0), device=ids.device)
        last_valid = out[row, lens - 1]        # [B,H], not padded output[:, -1]
        return self.classifier(last_valid)     # raw [B,2] logits

sentiment = SentimentModel(vocab_size).to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(sentiment.parameters(), lr=0.01)
for epoch in range(8):
    sentiment.train()
    for xb, lb, yb in train_loader:
        xb, lb, yb = xb.to(device), lb.to(device), yb.to(device)
        optimizer.zero_grad()
        logits = sentiment(xb, lb)
        loss = criterion(logits, yb)
        loss.backward()
        nn.utils.clip_grad_norm_(sentiment.parameters(), 1.0)
        optimizer.step()
    sentiment.eval()
    correct = total = 0
    with torch.no_grad():
        for xb, lb, yb in valid_loader:
            logits = sentiment(xb.to(device), lb.to(device))
            correct += (logits.argmax(1).cpu() == yb).sum().item()
            total += yb.numel()
    print(f"sentiment epoch {epoch+1}: val accuracy={correct/total:.3f}")

# ------------------------------------------------------------
# B. CHARACTER GENERATION: predict the next character
# ------------------------------------------------------------
text = ("deep learning learns patterns. " * 80)
chars = sorted(set(text))
char_to_id = {c: i for i, c in enumerate(chars)}
id_to_char = {i: c for c, i in char_to_id.items()}
ids = torch.tensor([char_to_id[c] for c in text], dtype=torch.long)
context = 20
X = torch.stack([ids[i:i+context] for i in range(len(ids)-context)])
y = ids[context:]
char_loader = DataLoader(TensorDataset(X, y), batch_size=64, shuffle=True)

class CharGRU(nn.Module):
    def __init__(self, vocab, emb=24, hidden=48):
        super().__init__()
        self.embedding = nn.Embedding(vocab, emb)
        self.gru = nn.GRU(emb, hidden, batch_first=True)
        self.head = nn.Linear(hidden, vocab)
    def forward(self, x):
        out, _ = self.gru(self.embedding(x))
        return self.head(out[:, -1])            # predict char after context

char_model = CharGRU(len(chars)).to(device)
char_opt = torch.optim.Adam(char_model.parameters(), lr=0.005)
for epoch in range(5):
    char_model.train()
    total_loss = 0.0
    for xb, yb in char_loader:
        xb, yb = xb.to(device), yb.to(device)
        char_opt.zero_grad()
        logits = char_model(xb)
        loss = criterion(logits, yb)
        loss.backward()
        nn.utils.clip_grad_norm_(char_model.parameters(), 1.0)
        char_opt.step()
        total_loss += loss.item()
    print(f"generation epoch {epoch+1}: mean batch loss="
          f"{total_loss/len(char_loader):.3f}")

def generate(prefix="deep learning", count=80, temperature=0.8):
    char_model.eval()
    context_ids = [char_to_id.get(c, 0) for c in prefix[-context:]]
    if len(context_ids) < context:
        context_ids = [0] * (context-len(context_ids)) + context_ids
    result = list(prefix)
    with torch.no_grad():
        for _ in range(count):
            x = torch.tensor([context_ids[-context:]], device=device)
            logits = char_model(x)[0] / temperature
            probs = torch.softmax(logits, dim=0)
            next_id = torch.multinomial(probs, 1).item()
            context_ids.append(next_id)
            result.append(id_to_char[next_id])
    return "".join(result)
print("generated sample:", generate())

# ------------------------------------------------------------
# C. FORECASTING: chronological split, windows, one-step target
# ------------------------------------------------------------
# Smooth signal plus small noise; real forecast data needs domain-aware baselines.
rng = np.random.default_rng(SEED)
time = np.arange(700, dtype=np.float32)
series = (np.sin(time * 0.045) + 0.25*np.sin(time * 0.13)
          + 0.04*rng.normal(size=len(time))).astype(np.float32)
train_end, val_end, lookback = 490, 595, 24
# Fit scaling on training observations only (before making any later windows).
mu, sigma = series[:train_end].mean(), series[:train_end].std()
scaled = (series - mu) / sigma

def windows_for_targets(first_target, last_target):
    xs, ys = [], []
    # target indices are [first_target, last_target); each input ends at target-1.
    for target in range(first_target, last_target):
        xs.append(scaled[target-lookback:target])
        ys.append(scaled[target])
    return (torch.tensor(np.asarray(xs), dtype=torch.float32).unsqueeze(-1),
            torch.tensor(np.asarray(ys), dtype=torch.float32).unsqueeze(-1))

Xtr, ytr = windows_for_targets(lookback, train_end)
Xva, yva = windows_for_targets(train_end, val_end)
Xte, yte = windows_for_targets(val_end, len(series))
train_forecast = DataLoader(TensorDataset(Xtr, ytr), batch_size=32, shuffle=True)

class ForecastLSTM(nn.Module):
    def __init__(self, hidden=32):
        super().__init__()
        self.lstm = nn.LSTM(input_size=1, hidden_size=hidden, batch_first=True)
        self.head = nn.Linear(hidden, 1)
    def forward(self, x):
        _, (h, _) = self.lstm(x)
        return self.head(h[-1])                   # [B,1]

forecaster = ForecastLSTM().to(device)
forecast_opt = torch.optim.Adam(forecaster.parameters(), lr=0.01)
for epoch in range(8):
    forecaster.train()
    for xb, yb in train_forecast:
        xb, yb = xb.to(device), yb.to(device)
        forecast_opt.zero_grad()
        pred = forecaster(xb)
        loss = F.mse_loss(pred, yb)
        loss.backward()
        nn.utils.clip_grad_norm_(forecaster.parameters(), 1.0)
        forecast_opt.step()
    forecaster.eval()
    with torch.no_grad():
        val_pred = forecaster(Xva.to(device)).cpu()
        val_mae_scaled = (val_pred - yva).abs().mean().item()
    print(f"forecast epoch {epoch+1}: val MAE (scaled)={val_mae_scaled:.3f}")

# Convert scaled predictions to original units for interpretable metrics.
forecaster.eval()
with torch.no_grad():
    pred_scaled = forecaster(Xte.to(device)).cpu().numpy().ravel()
pred_original = pred_scaled * sigma + mu
truth_original = yte.numpy().ravel() * sigma + mu
mae = np.mean(np.abs(pred_original - truth_original))
rmse = np.sqrt(np.mean((pred_original - truth_original)**2))
print(f"test MAE={mae:.3f}; RMSE={rmse:.3f}; units=series units")

Walkthrough and audit checklist

  1. Sentiment inputs: integer token IDs are padded; lengths preserve the actual sequence size. The last-valid-output gather excludes PAD suffixes.
  2. Classification: logits [B,2] and integer class IDs [B] match CrossEntropyLoss. Gradients are cleared, computed, clipped, then applied.
  3. Validation: eval mode and no-grad are used; neither changes parameters. The split is only a toy tail split; realistic data should split by time, user, or source as appropriate.
  4. Text generation: inputs and labels are shifted by one. At inference, the sampled output is appended to context; temperature changes the categorical distribution.
  5. Forecast: train scaling is fit before validation/test. Window targets belong to the split they are forecast for; earlier observed history can be context.
  6. Metrics: forecast metrics are reported after converting from standardized values back to the original units.
Production upgrades: replace synthetic sentiment labels and the repeated toy corpus with a real dataset; use a validation-based model-selection protocol, class-aware metrics, vocabulary and tokenizer saved with the checkpoint, and rolling-origin evaluation for forecasting.

8. Week 6 formula card and final checklist

Sequence / classifier

Input [B,T,F]; embedding [B,T,E]; logits [B,C]; LSTM count 4H(I+H)+8H with default biases.

Next-token objective

NLL=−Σtlog p(xt+1|x≤t); PPL=exp(mean NLL).

Forecast metrics

MAE=mean|y−ŷ|; RMSE=√mean((y−ŷ)²); report units and horizon.

Data integrity

Vocabulary and scaler fit on train only; chronological split; ignore PAD in sequence summaries and token loss.
