How to use the guide

Week 4 is the hands-on continuation of Week 3's CNN theory: build a CNN image classifier (examples include MNIST and CIFAR-10), train it, and evaluate it. The quiz papers use short PyTorch code-reading and shape/parameter questions, so this guide pairs implementation patterns with manual calculations.

Quiz emphasis that matters here: exact tensor shapes; preprocessing transforms that are defined versus actually attached; Conv2d input/output channel order; convolution parameter counts (bias included/excluded); pooling with zero parameters; flatten dimensions; CNN parameter subtotals; and training-loop bugs such as missing zero_grad(). These turn up as MCQs, one-or-more-correct statements, and short numerical answers.

The end-to-end order is: inspect data → split → transform → batch → define CNN → calculate shapes and parameter counts → choose loss/optimizer → train → validate → evaluate test once → inspect predictions and errors. Every stage has a contract. Check it before training rather than trying to interpret a loss curve from a broken pipeline.

Framework: the course Week 2 practice lists TensorFlow/Keras, but the supplied Quiz 1 papers predominantly ask PyTorch/torchvision code. This Week 4 guide uses PyTorch for the implementation patterns that match the papers. The underlying ideas are framework-independent.

1. What an image classifier does

An image classifier maps an image tensor to scores over a fixed set of classes. For a single image x, a CNN computes logits z∈ℝC, one score per class. Training compares logits with the correct class label using a classification loss such as cross-entropy.

image x → feature extractor fθ(x) → C logits → loss(logits, class ID)

Logits are not probabilities. Softmax turns them into a probability distribution when needed for interpretation; cross-entropy in PyTorch should receive the raw logits. Predicted class is usually logits.argmax(dim=1).

Classification objective

For a batch of B examples and C classes, logits have shape [B,C]; labels are integer class IDs of shape [B]. Cross-entropy for example i is −log softmax(zᵢ)yᵢ. The batch loss commonly averages across B.

Example: if true class is 7 and softmax probability p₇=.8, single-example loss=−ln(.8)≈.223. If true class probability=.1, loss≈2.303. Accuracy only looks at the top score; cross-entropy also evaluates confidence.

2. The datasets: MNIST, FashionMNIST, CIFAR-10

DatasetImage shape per exampleClassesNotes for a basic CNN
MNIST1×28×28 (grayscale)10 digits, 0–9Small; good first CNN exercise; low compute.
FashionMNIST1×28×28 (grayscale)10 clothing categoriesSame dimensions as MNIST, harder visual distinctions. Mean/std commonly used in course examples: about .286/.353.
CIFAR-103×32×32 (RGB)10 object categoriesColor images; more visual variability; normalize per RGB channel.

torchvision datasets return an image and target. The image's in-memory representation depends on whether a transform is supplied. A PIL image is not yet a model-ready float tensor. A standard PyTorch Conv2d expects a batch in NCHW order: MNIST [B,1,28,28], CIFAR-10 [B,3,32,32].

Training/validation/test roles

  • Training: loss gradients update weights.
  • Validation: compare epochs/model settings and choose early stopping; do not update weights.
  • Test: final performance estimate after decisions; avoid repeated tuning on it.

For image benchmarks, official test sets are often supplied. Use a validation subset from training for model selection. If randomly splitting, use a fixed seed; stratified splits help keep class proportions comparable.

3. Image pipeline: transforms, normalization, and batches

ToTensor

transforms.ToTensor() converts a PIL image or uint8 array to a floating tensor, changes channel order to C×H×W, and maps common 8-bit pixel values from [0,255] to [0,1]. Therefore a FashionMNIST image becomes [1,28,28], and an RGB CIFAR image becomes [3,32,32].

Normalize

x′c = (xc−μc)/σc

For grayscale, μ and σ are single numbers. For RGB, use one value per channel. Normalization centers and scales input distributions; it does not guarantee the output remains in [0,1]. After normalizing, values may be negative and may exceed 1.

FashionMNIST example uses μ=.2860 and σ=.3530. A pixel value .5 becomes (.5−.286)/.353≈.606. A pixel value 0 becomes −.286/.353≈−.810.

Compose order

Apply transforms in order. For most torchvision image workflows: crop/flip augmentation operates on image, ToTensor converts to tensor, Normalize adjusts tensor values. Many PIL-based augmentation transforms must run before ToTensor; tensor-based ones may run after.

transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.2860,), (0.3530,))
])
train_ds = datasets.FashionMNIST(
    root="./data",
    train=True,
    download=True,
    transform=transform  # attach transform to dataset
)
Exact PYQ trap: the March papers show a transform variable defined but omit transform=transform when constructing FashionMNIST. Defining a Compose object does not apply it. Without attachment, returned images remain untransformed PIL images. Dataset transforms are typically called lazily in __getitem__ when a sample is requested.

DataLoader

DataLoader batches examples, optionally shuffles training order, and can use worker processes. For batch size B, image batch shape is [B,C,H,W], label shape [B]. Training usually uses shuffle=True; validation/test usually use shuffle=False. The final batch may be smaller unless drop_last=True.

Normalize channel tuples correctly

For grayscale use one-element tuples: Normalize((mean,), (std,)). For RGB, length-three tuples, e.g. Normalize((.49,.48,.45),(.20,.20,.20)). Means/stds must match channel count. Applying 3-channel normalization to a one-channel image is a shape/configuration error.

4. Build a CNN image classifier

Feature extractor and classifier head

A basic CNN repeatedly extracts local features with convolution, applies nonlinearity, optionally downsamples, and ends with a classification head. For a simple MNIST CNN:

image → Conv → ReLU → Pool → Conv → ReLU → Pool → Flatten → Dense → logits

Convolution preserves useful spatial structure. Pooling reduces H,W while preserving channels. Flatten converts C×H×W into a vector. Dense layers combine learned features to produce class scores.

Design choices

  • in_channels: number of channels in each input image (1 grayscale, 3 RGB).
  • out_channels: number of learned filters/feature maps.
  • kernel_size: local pattern extent, often 3×3.
  • padding: controls spatial size; for 3×3 stride 1, padding 1 preserves H,W.
  • pooling: often 2×2 stride 2 halves each spatial dimension.
  • final output width: number of classes (10 for MNIST, FashionMNIST, CIFAR-10).

Why logits rather than softmax in the model?

PyTorch's CrossEntropyLoss combines log-softmax and negative log likelihood stably. Return raw logits from the model. During evaluation, argmax(logits) gives the predicted class. Apply softmax only if you need probabilities for inspection/calibration.

5. Shape-tracing example: every layer

Input MNIST batch [B,1,28,28]. Use Conv 1→16, 3×3, stride1,padding1; MaxPool2; Conv16→32, 3×3,padding1; MaxPool2; flatten; Dense to 128; Dense to 10.

OperationOutput shapeWhy
Input[B,1,28,28]Batch, channel, height, width
Conv1[B,16,28,28]Padding1 preserves 28; 16 filters create 16 channels
ReLU[B,16,28,28]Elementwise, shape unchanged
MaxPool 2×2,s2[B,16,14,14]Halves H,W; channels unchanged
Conv2 16→32[B,32,14,14]Padding1 preserves spatial size
Pool 2×2,s2[B,32,7,7]Halves 14 to 7
Flatten from dim1[B,1568]32×7×7=1568 features
Linear 1568→128[B,128]128 hidden values
Linear 128→10[B,10]10 class logits

For CIFAR-10, the same shape formulas apply, but input is [B,3,32,32]. If the same two conv/pool stages are used: after first conv/pool 16×16, after second conv/pool 8×8. With 32 channels, flatten has 32×8×8=2,048 features.

Flatten trap: for PyTorch NCHW data, use torch.flatten(x, start_dim=1). It preserves batch axis. Flattening from dimension 0 accidentally merges examples and features.

6. Training loop: from minibatch to updated filters

Training adjusts convolution kernels, biases, and dense weights together. Cross-entropy gives a loss; backpropagation calculates gradients through convolution and pooling; optimizer updates parameters. A standard update cycle is:

zero_grad → forward → loss → backward → optimizer.step

PyTorch accumulates gradients by default. If you omit optimizer.zero_grad(), each backward() adds to the existing gradient buffer. This can cause wrong updates; both March Quiz 1 sets ask about this bug.

Correct train/evaluation modes

SettingEffectDoes it turn off gradients?
model.train()Dropout active; BatchNorm uses batch stats.No
model.eval()Dropout disabled; BatchNorm uses running stats.No
torch.no_grad()Stops autograd graph construction.Yes, in that context

eval() and no_grad() are distinct. Evaluation commonly uses both. Calling model.eval() is not a requirement for optimizer updates, nor does it update parameters by itself.

Epoch-level loss/accuracy calculation

If batch loss is a mean, multiply it by batch size before summing to obtain an epoch average when batches differ in size. Accuracy count should accumulate correct predictions and divide by total examples.

running_loss += loss.item() * images.size(0)
correct += (logits.argmax(dim=1) == labels).sum().item()
total += labels.size(0)
epoch_loss = running_loss / total
epoch_accuracy = correct / total

7. Evaluate performance and inspect errors

Accuracy is the fraction of correct class predictions. On balanced MNIST it is a useful first summary, but it can conceal a class-specific failure. Use a confusion matrix to see which true classes are mistaken for which predicted classes.

Confusion matrix orientation

One common convention uses rows for true class and columns for predicted class; verify plotting library convention. Diagonal entries are correct. Off-diagonal entries identify confusions. For class k:

precisionₖ=TPₖ/(TPₖ+FPₖ) ; recallₖ=TPₖ/(TPₖ+FNₖ)

Macro averages weight classes equally. Weighted averages weight by class frequency. For a balanced dataset, the two may be close; for an imbalanced dataset, they can differ substantially.

Look at examples, not only a scalar

  • Show the image, true class, predicted class, and confidence.
  • Inspect false positives and false negatives per class.
  • Check whether mistakes are ambiguous or systematic (e.g. transform bug, label mapping, channel normalization).
  • For confidence, remember neural-network softmax may be overconfident; a high max probability is not proof of correctness.

Never tune architecture based repeatedly on the test set. Use validation for model selection and retain test for final reporting.

8. Data augmentation and generalization

Augmentation creates label-preserving variations of training images, such as small crops or horizontal flips when orientation does not change the class. It improves robustness by exposing the model to plausible variation; it does not create new independent labels or fix data leakage.

Dataset/taskPotentially sensibleUse caution / usually invalid
MNIST digitsSmall translations, slight affine changes.Horizontal flips can turn a digit into an implausible or different symbol; large rotations change identity.
FashionMNISTSmall crops/translations; modest variation.Vertical flips often make garments unrealistic.
CIFAR-10Random crop, horizontal flip, mild color jitter.Excessive distortions/color shifts can remove class-defining cues.

Augmentation belongs only in training pipeline. Validation/test transforms should be deterministic and match expected evaluation preprocessing (typically ToTensor + Normalize). Augmenting test data inconsistently changes what is being measured.

Overfitting and remedies

Training loss decreases while validation loss rises: overfitting is plausible. Consider more training data, suitable augmentation, weight decay, dropout, smaller model, or early stopping. If both losses remain high, diagnose optimization, labels, input pipeline, and model capacity before adding regularization.

10. Worked numerical examples

A. Conv shape + parameter count

Input [B,3,32,32]; Conv2d(3,16,k=3,s=1,p=1,bias=True). Spatial size: floor((32+2−3)/1)+1=32. Output [B,16,32,32]. Parameters: 3×3×3×16+16=448.

B. Pool then pointwise conv (March pattern)

6×6×2 → MaxPool2,stride2 =3×3×2. Conv1×1 with 4 filters =3×3×4. Shape answer: 3×3×4. The pointwise conv parameter count with bias would be 1×1×2×4+4=12; without bias, 8.

C. Inception channel concatenation

28×28×64, 28×28×128, 28×28×32, 28×28×32. Same spatial shape, so concatenate channels: 64+128+32+32=256. Output 28×28×256.

D. Receptive field

Three 3×3 convs, stride1: R₀=1, each adds 2; R=1+2+2+2=7. Answer 7×7. Do not use 3×3×3=27 or 9×9.

E. SAME padding

Stride1, K5: P=(5−1)/2=2. K3: P=1. Input 32×32 remains 32×32 for either odd kernel.

F. FC versus convolution parameters

10×10 grayscale→5 classes. Dense(100,5), no bias: 100×5=500. Five 10×10 Conv filters, C_in=1, no bias: 10×10×1×5=500. Equal in this example.

G. GAP vs flatten parameter calculation

Feature map 7×7×512, class count 10. Flatten size 25,088; Dense has 25,088×10+10=250,890 parameters. GAP size 512; Dense has 512×10+10=5,130. GAP+Dense saves 245,760 dense weights/bias parameters relative to flatten head.

H. Full-network parameter count (exam-notes pattern)

  1. Conv1: 3 input channels, 16 filters, 3×3, bias: 3×3×3×16+16=448.
  2. Conv2: 16 input channels, 32 filters, 3×3, bias: 3×3×16×32+32=4,640.
  3. If pooling yields 32×8×8, flatten size=2,048.
  4. FC 2,048→128: 2,048×128+128=262,272.
  5. FC 128→10: 128×10+10=1,290.
  6. Total: 448+4,640+262,272+1,290=268,650.

Always derive the flatten size from the actual convolution/pooling settings; this example assumes the feature-map size is 8×8 at fc1.

I. BatchNorm parameter count

BatchNorm2d on C=64 feature channels learns γ and β per channel: 2×64=128 trainable parameters. Running mean/variance are buffers, not learned parameters.

J. Accuracy from counts

Correct predictions=870 out of 1,000: accuracy=.87=87%. If a rare class has 5/20 correct but majority classes are near-perfect, overall accuracy may still look high; use classwise recall/confusion matrix to diagnose.

13. Practice questions with solutions

Q1. MNIST batch has shape [32,1,28,28]. Which Conv2d input channels?

1. PyTorch uses NCHW, so channel axis is dimension 1.

Q2. Transform is defined but absent from dataset constructor. Does dataset return normalized tensors?

No. The transform must be passed via transform=...; otherwise it is not applied.

Q3. Conv(1→8,k=3,p=1,s=1), followed by pool 2,s2. Input 28×28. Output shape?

Conv preserves 28; pool gives 14. Full batch output [B,8,14,14].

Q4. Count Conv parameters in Q3, bias included.

3×3×1×8+8=80.

Q5. Input [B,8,14,14], 2×2 pool stride2, then 1×1 Conv with 12 outputs. Shape?

Pool→[B,8,7,7]; pointwise Conv→[B,12,7,7].

Q6. A model has 64 channels and uses BatchNorm2d. Learnable parameter count?

2×64=128, one γ and β per channel.

Q7. Why does missing zero_grad create wrong updates in PyTorch?

Gradients accumulate in parameter .grad across backward passes unless cleared.

Q8. CIFAR-10 model receives RGB images. What are batch shape and first Conv2d in_channels?

Typical tensor [B,3,32,32]; first layer in_channels=3.

Q9. For [B,32,7,7], what is flatten width and how to preserve B?

32×7×7=1568. Use torch.flatten(x,start_dim=1).

Q10. Should softmax be applied before CrossEntropyLoss?

No. Pass raw logits; CrossEntropyLoss handles stable log-softmax internally.

Q11. Does doubling image height/width double Conv parameter count?

No if kernel size and channel counts stay fixed. It increases output positions/compute, not shared weights.

Q12. Explain why GAP can drastically reduce classifier parameters.

It maps H×W×C to C features before Dense, instead of HWC, so the Dense input width is much smaller.

15. Complete program at the end: train a small MNIST CNN

This example is intentionally complete and follows the quiz-relevant PyTorch patterns: transform attachment, NCHW shapes, correct Conv2d arguments, explicit parameter count, loss on logits, device handling, training-loop order, validation mode, and final test evaluation.

import torch
from torch import nn
from torch.utils.data import DataLoader, random_split
from torchvision import datasets, transforms

# ------------------------------------------------------------
# 1) Reproducibility, device, and image transforms
# ------------------------------------------------------------
torch.manual_seed(7)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# MNIST is grayscale. ToTensor converts to float [0,1], shape [1,28,28].
# Normalize uses training-set mean/std for MNIST.
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,))
])

# Important: pass transform=transform so dataset applies the pipeline.
full_train = datasets.MNIST(
    root="./data", train=True, download=True, transform=transform
)
test_ds = datasets.MNIST(
    root="./data", train=False, download=True, transform=transform
)

# Reserve validation examples for model selection.
train_ds, val_ds = random_split(
    full_train, [50000, 10000],
    generator=torch.Generator().manual_seed(7)
)
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=128, shuffle=False)
test_loader = DataLoader(test_ds, batch_size=128, shuffle=False)

# ------------------------------------------------------------
# 2) CNN architecture: [N,1,28,28] -> [N,10] logits
# ------------------------------------------------------------
class MNISTCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(
            in_channels=1, out_channels=16,
            kernel_size=3, stride=1, padding=1
        )
        self.conv2 = nn.Conv2d(
            in_channels=16, out_channels=32,
            kernel_size=3, stride=1, padding=1
        )
        self.pool = nn.MaxPool2d(kernel_size=2, stride=2)
        self.relu = nn.ReLU()
        self.fc1 = nn.Linear(32 * 7 * 7, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = self.relu(self.conv1(x))   # [N,1,28,28] -> [N,16,28,28]
        x = self.pool(x)               # -> [N,16,14,14]
        x = self.relu(self.conv2(x))   # -> [N,32,14,14]
        x = self.pool(x)               # -> [N,32,7,7]
        x = torch.flatten(x, start_dim=1)  # -> [N,1568]
        x = self.relu(self.fc1(x))     # -> [N,128]
        return self.fc2(x)             # -> [N,10] raw logits

model = MNISTCNN().to(device)

# Verify learned parameter total:
# conv1 = 3*3*1*16 + 16 = 160
# conv2 = 3*3*16*32 + 32 = 4640
# fc1   = (32*7*7)*128 + 128 = 200832
# fc2   = 128*10 + 10 = 1290
# total = 206922
print("trainable parameters:",
      sum(p.numel() for p in model.parameters() if p.requires_grad))

# ------------------------------------------------------------
# 3) Configure the objective and optimizer
# ------------------------------------------------------------
# CrossEntropyLoss expects [N,10] logits and [N] integer labels.
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# ------------------------------------------------------------
# 4) Train the network
# ------------------------------------------------------------
for epoch in range(5):
    model.train()  # dropout/batchnorm training behavior, if present
    loss_sum, correct, count = 0.0, 0, 0

    for images, labels in train_loader:
        images = images.to(device)  # [N,1,28,28]
        labels = labels.to(device)  # [N], integer IDs 0...9

        optimizer.zero_grad()       # clear previous batch gradients
        logits = model(images)      # forward pass
        loss = criterion(logits, labels)
        loss.backward()             # chain rule: compute d(loss)/d(params)
        optimizer.step()            # update model parameters

        batch_size = labels.size(0)
        loss_sum += loss.item() * batch_size
        correct += (logits.argmax(dim=1) == labels).sum().item()
        count += batch_size

    train_loss = loss_sum / count
    train_accuracy = correct / count

    # --------------------------------------------------------
    # 5) Validate: no optimizer update
    # --------------------------------------------------------
    model.eval()
    val_loss_sum, val_correct, val_count = 0.0, 0, 0
    with torch.no_grad():
        for images, labels in val_loader:
            images, labels = images.to(device), labels.to(device)
            logits = model(images)
            loss = criterion(logits, labels)
            batch_size = labels.size(0)
            val_loss_sum += loss.item() * batch_size
            val_correct += (logits.argmax(dim=1) == labels).sum().item()
            val_count += batch_size

    val_loss = val_loss_sum / val_count
    val_accuracy = val_correct / val_count
    print(
        f"epoch {epoch + 1}: "
        f"train loss={train_loss:.4f}, accuracy={train_accuracy:.4f}; "
        f"val loss={val_loss:.4f}, accuracy={val_accuracy:.4f}"
    )

# ------------------------------------------------------------
# 6) Test once after model choices are complete
# ------------------------------------------------------------
model.eval()
test_correct, test_count = 0, 0
with torch.no_grad():
    for images, labels in test_loader:
        images, labels = images.to(device), labels.to(device)
        logits = model(images)
        test_correct += (logits.argmax(dim=1) == labels).sum().item()
        test_count += labels.size(0)

print("test accuracy:", test_correct / test_count)

# ------------------------------------------------------------
# 7) Inspect one prediction
# ------------------------------------------------------------
images, labels = next(iter(test_loader))
images = images.to(device)
with torch.no_grad():
    logits = model(images[:1])               # [1,10]
    probabilities = logits.softmax(dim=1)   # optional display
    prediction = logits.argmax(dim=1)

print("true class:", labels[0].item())
print("predicted class:", prediction.item())

Walkthrough of the complete program

  1. Transforms: ToTensor converts PIL to float/channel-first and scales; Normalize standardizes. The transform is actually attached to both datasets.
  2. Split: validation comes from training data. Test data stays separate until final reporting.
  3. Input contract: DataLoader emits [N,1,28,28] for MNIST, compatible with Conv2d(1,...).
  4. Convolution shapes: padding 1 with 3×3 stride 1 preserves spatial size. Pool halves 28→14→7.
  5. Flatten: 32×7×7=1,568 values per example; start_dim=1 preserves batch axis.
  6. Classifier: final Linear returns ten logits, one per digit.
  7. Parameter total: conv1 160 + conv2 4,640 + fc1 200,832 + fc2 1,290 = 206,922. Pool/ReLU/flatten add zero.
  8. Loss: CrossEntropyLoss gets raw logits and integer IDs. Do not softmax before it.
  9. Training: zero_grad → forward → loss → backward → step. Omitting zero_grad causes gradients to accumulate, the bug highlighted in the PYQs.
  10. Validation: eval mode and no_grad; no optimizer update. Test is reserved for final evaluation.
  11. Prediction: argmax logits gives the class; softmax is used only to display class probabilities.
Final shape audit: [N,1,28,28] → [N,16,28,28] → [N,16,14,14] → [N,32,14,14] → [N,32,7,7] → [N,1568] → [N,128] → [N,10].
