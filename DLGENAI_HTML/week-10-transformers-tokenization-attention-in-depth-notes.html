How to use these notes

A Transformer replaces recurrence with attention: each token builds a representation by weighting other token representations. This week starts with token IDs and embeddings, builds scaled dot-product and multi-head attention, then connects these ideas to the full Transformer and exam numericals.

Quiz-paper alignment: The supplied Quiz 1 papers are dominated by early-week code/output, tensor-shape, parameter-count, and numerical questions; the provided exam notes specifically predict attention Q/K/V and positional-encoding questions. There are few direct Transformer PYQs in these papers. The worked problems below therefore follow the same short-numeric, code-trace, conceptual-distractor and shape-audit styles, and are labeled as practice patterns.

1. Tokenization and word embeddings

1.1 Text becomes token IDs, not words-as-vectors

A tokenizer divides text into units chosen by its vocabulary: whole words, subwords, bytes, or a hybrid. It adds special tokens such as beginning/end markers, classification separators, or padding depending on model and task. Token count is not word count: “unbelievable” might become one token or multiple pieces. The model receives integer IDs and converts each ID to a trainable/dense vector through an embedding matrix.

IDs [B,T] → embedding table E∈RV×d → vectors X∈RB×T×d

V is vocabulary size and d is model width. Embedding parameters=Vd if there is no padding row freeze or tied output. If the vocabulary is 30,000 and d=512, that table has 15,360,000 weights. A decoder language model may tie its output projection to the input embedding, so count once when the weights are shared.

1.2 Word embeddings vs contextual representations

The embedding lookup gives a starting vector for each token. Transformer layers update it using surrounding context. The same word/token can therefore have different final contextual vectors in different sentences. Static word vectors have one learned vector per vocabulary item; contextual states depend on the sequence and position.

1.3 Padding and attention masks

Batching variable-length text often adds PAD tokens. An attention mask usually marks real tokens as 1 and padding as 0. The mask prevents a query from attending to padding keys. It is different from a causal mask, which prevents each position from seeing later positions. Some APIs use the inverse boolean convention: always read the function’s documentation.

batch = tokenizer(texts, padding=True, truncation=True,
                  return_tensors="pt")
input_ids = batch["input_ids"]          # [B,T]
attention_mask = batch["attention_mask"]  # 1=real, 0=padding (HF convention)
Quiz-style trap: Tokenizer padding mask is not the same as the decoder’s future-blocking causal mask. A causal decoder can also need a padding mask when examples have different lengths.

2. Scaled dot-product attention

2.1 Query, key, value

For each token, learned linear maps create a query Q, key K, and value V. A query asks what information to retrieve; keys are matched against it; values carry the content to mix. Similarity scores QKᵀ are scaled by √dk, softmax-normalized over key positions, and used to average V.

Attention(Q,K,V)=softmax(QKᵀ/√dk + mask)V

For sequence length T, Q,K,V per head have shapes [B,T,dk]. Scores/weights have [B,T,T]. For each query, weights sum to one over keys if at least one key is allowed. The scale controls logit magnitude; without it, dot products can grow with dk and softmax may become too peaked.

2.2 Hand calculation: two keys, two values

Let q=[1,0], k₁=[1,0], k₂=[0,1], v₁=[10,0], v₂=[0,10], dk=2. Raw dot products are [1,0]. Divide by √2: scores [.7071,0]. Softmax gives approximately [.6698,.3302]. The output is .6698[10,0]+.3302[0,10]=[6.698,3.302]. The first value has more weight because its key aligns with q.

2.3 Why softmax is over keys

Each query produces one row of scores over all keys. Normalize along that key axis, then multiply by the values. Softmax on the query axis would answer a different question and often creates a shape-correct but conceptually wrong implementation.

# Q,K,V: [B,heads,T,head_dim]
scores = Q @ K.transpose(-2, -1) / math.sqrt(head_dim)
weights = torch.softmax(scores, dim=-1)  # normalize over key positions
context = weights @ V                  # [B,heads,T,head_dim]

3. Multi-head attention and Transformer block

3.1 Project, split into heads, combine

Given X [B,T,dmodel], learned WQ,WK,WV create Q,K,V. With h heads, split width dmodel into dk=dmodel/h per head, attend independently, concatenate, and apply output projection WO. Each head can learn a different relationship pattern; it is not guaranteed each head has a human-readable role.

headi=Attention(XWQi,XWKi,XWVi)
MHA=Concat(head₁,…,headh)WO

If dmodel=512 and h=8, each head width is 64. A common shape pipeline is [B,T,512]→[B,8,T,64] for Q/K/V, scores [B,8,T,T], context [B,8,T,64], concatenate back to [B,T,512].

3.2 Residual, normalization, feed-forward network

A Transformer layer combines attention and position-wise feed-forward networks (FFNs), using residual connections and LayerNorm (pre-norm or post-norm order depends on architecture). FFN maps each token independently through two learned projections, e.g. d→dff→d with a nonlinearity. Residuals offer a short path through the layer; LayerNorm normalizes feature statistics within each token, unlike BatchNorm’s batch/spatial aggregation.

3.3 Positional information

Self-attention alone is permutation-equivariant: permuting token order and corresponding rows/columns permutes outputs in the same way; it does not inherently know “first” or “next.” Add positional information using learned position embeddings, sinusoidal encodings, relative position methods, or rotary embeddings depending on architecture.

PE(pos,2i)=sin(pos / 100002i/d)
PE(pos,2i+1)=cos(pos / 100002i/d)

Worked component: d=4, pos=1. For i=0, denominator=1, so PE(1,0)=sin(1)≈.8415 and PE(1,1)=cos(1)≈.5403. For i=1, denominator=100002/4=100, so PE(1,2)=sin(.01)≈.0100 and PE(1,3)=cos(.01)≈.99995. Frequencies vary across feature pairs.

3.4 Attention masks

  • Padding mask: ignore filler tokens in batch.
  • Causal mask: target position t cannot attend to positions greater than t. Apply before softmax by setting forbidden scores to −∞ (or a sufficiently negative value).
  • Cross-attention mask: decoder queries may ignore padded encoder keys.

For a causal sequence of length 4, allowed matrix (query rows, key columns) is lower triangular: position 0 sees only 0; position 1 sees 0–1; position 2 sees 0–2; position 3 sees 0–3. During parallel training, all target positions are processed at once, but the mask prevents future-token leakage.

3.5 Complexity and long contexts

Dense attention scores require O(T²) entries per head and O(T²d) matrix multiply cost for sequence length T and width d. Doubling T roughly quadruples the attention matrix. Linear projections and FFNs scale roughly linearly with T (for fixed width), but long contexts are often dominated by attention memory/compute. Sparse, local, grouped-query, and other efficient variants change the tradeoff.

4. Solved Transformer numericals

Numerical A: score scaling and output

For query q=[1,0], keys k₁=[1,0], k₂=[0,1] and dk=2, scaled logits=[1/√2,0]=[.7071,0]. Softmax ≈ [.6698,.3302]. For values [10,0] and [0,10], context ≈ [6.698,3.302]. Show the division by √dk before softmax.

Numerical B: tensor shape in multi-head attention

B=2, T=5, dmodel=64, h=4. Then dk=16; Q,K,V shape [2,4,5,16]; score shape [2,4,5,5]; context [2,4,5,16]; concatenated output [2,5,64]. Attention weights sum to 1 across the last axis (keys) for every [batch,head,query], absent all-masked rows.

Numerical C: parameter count for Q/K/V/output projections

For d=64 and four dense d→d maps (Q,K,V,O), weights=4d²=4×4096=16,384. With one bias of width d per map, add 4×64=256, total 16,640. This does not include FFN, embeddings, LayerNorm, or other Transformer blocks.

Numerical D: embedding and positional parameter count

Vocabulary V=20,000, model width d=256, maximum learned context length P=512: token embedding=20,000×256=5,120,000; learned position embedding=512×256=131,072; total=5,251,072 before any tied output projection. Sinusoidal position encodings have no trainable parameters.

Numerical E: attention scaling

For q·k=4 and dk=16, scaled score=4/√16=1. For q·k=4 and dk=64, scaled score=.5. Larger key dimension is scaled to control typical dot-product magnitude.

Numerical F: sequence length cost

For T=1,024, one head’s score matrix has T²=1,048,576 entries per batch item. At T=2,048, it has 4,194,304—four times more. With 12 heads and B=2, the second configuration has 100,663,296 score values before accounting for dtype/intermediates.

5. Exam-style practice with worked solutions

Q1. Why add positional information to self-attention?

Content-only self-attention does not encode token order. Positional information lets the model distinguish different arrangements and use relative/absolute position cues.

Q2. For Q,K,V shape [B,8,T,64], what is the score shape?

QKᵀ over the final feature dimension gives [B,8,T,T]. The last two axes are query positions and key positions.

Q3. Along which dimension does softmax normalize in ordinary attention?

Over the keys for each query; with the shape above, dim=−1.

Q4. What is forbidden by a causal mask?

A position t cannot use any key from a future position greater than t. This prevents next-token training from seeing its answer.

Q5. A four-head model has d_model=256. What is each head width if evenly split?

256/4=64 features per head.

Q6. Is a Transformer attention score matrix linear or quadratic in sequence length?

Quadratic: it contains T×T scores for each head and batch item.

6. Complete end-of-week program: train a tiny decoder-only Transformer

This fully self-contained character-level language-model lab uses a tiny repeated text corpus to demonstrate token IDs, embeddings, learned positions, causal self-attention, next-token loss, and autoregressive sampling. It is an architecture exercise, not a useful pretrained LLM.

"""Week 10 lab: a tiny GPT-style decoder-only Transformer."""
import math
import torch
from torch import nn
from torch.nn import functional as F

SEED = 41
torch.manual_seed(SEED)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# Character-level tokens keep this example self-contained and inspectable.
text = ("attention lets each token read useful context. " * 200)
chars = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}
data = torch.tensor([stoi[ch] for ch in text], dtype=torch.long)
vocab_size = len(chars)
BLOCK, BATCH = 48, 32

# Split in sequence order; never train on the future tail.
split = int(0.9 * len(data))
train_data, val_data = data[:split], data[split:]

def get_batch(source, batch_size=BATCH):
    starts = torch.randint(len(source) - BLOCK - 1, (batch_size,))
    x = torch.stack([source[i:i+BLOCK] for i in starts])
    y = torch.stack([source[i+1:i+BLOCK+1] for i in starts])
    return x.to(device), y.to(device)          # both [B,T]

class DecoderBlock(nn.Module):
    def __init__(self, width, heads, expansion=4, dropout=0.1):
        super().__init__()
        self.norm1 = nn.LayerNorm(width)
        self.attn = nn.MultiheadAttention(
            width, heads, dropout=dropout, batch_first=True
        )
        self.norm2 = nn.LayerNorm(width)
        self.ffn = nn.Sequential(
            nn.Linear(width, expansion*width), nn.GELU(),
            nn.Linear(expansion*width, width), nn.Dropout(dropout)
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, causal_mask):
        h = self.norm1(x)
        # In PyTorch bool attn_mask=True marks a forbidden query-key pair.
        attended, _ = self.attn(h, h, h, attn_mask=causal_mask,
                                need_weights=False)
        x = x + self.dropout(attended)
        x = x + self.ffn(self.norm2(x))
        return x

class TinyGPT(nn.Module):
    def __init__(self, vocab, width=96, heads=4, layers=2, block=BLOCK):
        super().__init__()
        self.block_size = block
        self.token_embedding = nn.Embedding(vocab, width)
        self.position_embedding = nn.Embedding(block, width)
        self.blocks = nn.ModuleList([
            DecoderBlock(width, heads) for _ in range(layers)
        ])
        self.final_norm = nn.LayerNorm(width)
        self.lm_head = nn.Linear(width, vocab, bias=False)
        # Tie output classifier to token embeddings to reduce parameters.
        self.lm_head.weight = self.token_embedding.weight

    def forward(self, idx, targets=None):
        b, t = idx.shape
        if t > self.block_size:
            raise ValueError("input longer than configured context")
        pos = torch.arange(t, device=idx.device)
        x = self.token_embedding(idx) + self.position_embedding(pos)[None, :, :]
        causal = torch.triu(
            torch.ones(t, t, device=idx.device, dtype=torch.bool), diagonal=1
        )
        for block in self.blocks:
            x = block(x, causal)
        logits = self.lm_head(self.final_norm(x)) # [B,T,V]
        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits.reshape(b*t, vocab_size), targets.reshape(b*t)
            )
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, new_tokens, temperature=0.8):
        self.eval()
        for _ in range(new_tokens):
            context = idx[:, -self.block_size:]
            logits, _ = self(context)
            next_logits = logits[:, -1, :] / temperature
            probabilities = torch.softmax(next_logits, dim=-1)
            next_id = torch.multinomial(probabilities, num_samples=1)
            idx = torch.cat([idx, next_id], dim=1)
        return idx

model = TinyGPT(vocab_size).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
print("vocab:", vocab_size,
      "trainable parameters:", sum(p.numel() for p in model.parameters()
                                     if p.requires_grad))

for step in range(800):
    model.train()
    xb, yb = get_batch(train_data)
    _, loss = model(xb, yb)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()
    if step % 100 == 0:
        model.eval()
        with torch.no_grad():
            vx, vy = get_batch(val_data)
            _, val_loss = model(vx, vy)
        print(f"step {step}: train={loss.item():.3f}, "
              f"validation={val_loss.item():.3f}")

start = torch.tensor([[stoi["a"]]], device=device)
output_ids = model.generate(start, new_tokens=180, temperature=0.8)[0].tolist()
print("sample:", "".join(itos[i] for i in output_ids))

Walkthrough

  1. Tokenization: characters receive IDs; a real LLM normally uses subword/byte tokenizer with special tokens.
  2. Next-token targets: y is x shifted one position. At each index, predict the following character.
  3. Position embeddings: token vector and position vector are added; context length cannot exceed BLOCK in this implementation.
  4. Causal mask: upper-triangular True entries block future key positions; training remains parallel across the sequence.
  5. Attention output: [B,T,width] enters and leaves each attention block; FFN acts independently per token.
  6. Logits/loss: [B,T,V] is flattened to [B×T,V], labels to [B×T], and cross entropy compares each next-token target.
  7. Generation: feed the most recent context, sample from the last position, append one token, repeat.
  8. Limits: the repeated toy corpus has narrow vocabulary and data; loss/samples teach mechanics only.
Exam connection: If asked for output dimensions, state batch B, sequence T, model width d, heads h, per-head width d/h, attention score [B,h,T,T], and logits [B,T,V]. Then inspect mask polarity and softmax axis.

7. Formula card and references

Attention

softmax(QKᵀ/√dk + mask)V; normalize over keys.

Head width

dk=dmodel/h, when width is split evenly.

Dense attention scores

[B,h,T,T]; memory/cost grows quadratically in T.

Positional encoding

Supplies order signal; sinusoidal/learned/relative choices vary by model.
