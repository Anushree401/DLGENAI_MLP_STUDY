So this guide uses the papers' general style—small numerical setups, tensor-shape tracing, multi-part comprehension, code semantics—and applies it to the Week 5 syllabus rather than claiming these exact RNN questions appeared in the papers.

Recommended order: sequence notation → vanilla RNN step → unroll across time → gradient flow → LSTM gates → numerical practice → PyTorch shapes/code. For hand calculations, write values at each time step and keep hidden state and cell state distinct.

Notation: t is time index, xₜ is input at time t, hₜ is hidden state, cₜ is LSTM cell state, yₜ is output. ⊙ means elementwise multiplication; [a,b] means vector concatenation. Matrix orientation differs across books; the equations here use column-vector intuition, while PyTorch accepts batch-first sequences [B,T,F] when configured.

1. What is sequential data?

A sequence is an ordered collection (x₁,x₂,…,xₜ). Order carries meaning: “dog bites person” and “person bites dog” contain similar words but describe different relations. Sequence examples include text tokens, sensor streams, speech frames, video frames, and event histories.

What makes it different from a fixed-size feature vector?

  • Sequence length T can vary across examples.
  • Earlier values may inform later predictions.
  • The same type of update is reused at every time step.
  • Outputs may be needed at every step or only once for the whole sequence.
  • Training must account for dependencies across time.

Sequence notation and batch representation

For B examples with common padded length T and F input features per time step, a batch is often [B,T,F]. At one time step, xₜ is [B,F]. Hidden state hₜ is [B,H]. An embedding sequence of token IDs first maps each token to an embedding vector, so F is embedding dimension.

Example: a batch of 32 tokenized sentences padded to length 50, using 100-dimensional embeddings, has embedded input shape [32,50,100]. If LSTM hidden size is 64, output over all steps is [32,50,64] for a one-direction, one-layer model.

2. Common sequence task patterns

Task typeInput sequencePrediction targetExample
Many-to-onex₁…xₜOne output after sequenceSentiment classification; activity class
Many-to-many, alignedx₁…xₜOutput at each stepPOS tag per token; frame labeling
Sequence forecastingPast observationsFuture value(s)Next-hour temperature
Sequence-to-sequenceSource sequenceTarget sequence, possibly different lengthTranslation; summarization

The recurrent core can be the same; the output head and loss differ. Many-to-one often uses final valid hidden state. Aligned tagging predicts from every hₜ. Forecasting may use the final state to predict one or more future values. Encoder-decoder sequence-to-sequence systems require additional mechanisms for output generation and variable target length.

Handling variable lengths

Batching variable-length sequences requires padding to a common T or grouping similar lengths. Padding tokens/zeros are not real data; models and losses must not treat them as meaningful observations. Common strategies: mask padded positions in loss/pooling; use packed sequences in PyTorch; or bucket sequences by length. For many-to-one, gather the hidden state at each example's last valid step—not blindly at the final padded position.

3. Vanilla recurrent neural network (RNN)

Recurrent update

An RNN carries a hidden summary of the past. Each step combines current input and previous hidden state:

hₜ = tanh(Wxhxₜ + Whhhₜ₋₁ + bh)

An output may be computed from the hidden state:

oₜ=Whyhₜ+by ;   ŷₜ=ψ(oₜ)

ψ depends on task: identity for real-valued regression, sigmoid for binary probability, softmax for categorical probabilities. In PyTorch training, often return logits instead and let a stable loss apply the appropriate transformation internally.

Why “recurrent”?

The hidden state from one step feeds the next. The same matrices Wxh, Whh, and bias are reused at every time step. This is parameter sharing across time. A sequence with T=10 and one with T=100 use the same learned parameter count, but longer sequences require more computation and a longer gradient path.

RNN as a state machine

hₜ is not a perfect record of all previous inputs. It is a learned fixed-width summary, updated at each step. It can encode recent context, but a simple tanh RNN often struggles to preserve information for long durations. The initial state h₀ is commonly zeros or a learned state; for independent sequences, reset it between sequences unless stateful streaming is intended.

RNN vs applying an MLP independently at every time step

An MLP independently computes f(xₜ) and has no memory of xₜ₋₁. The recurrent term Whhhₜ₋₁ is precisely what allows an RNN's current representation to depend on previous inputs. If Whh=0, the recurrence loses that dependency.

4. Unrolling through time and backpropagation through time

During forward pass, recurrence is evaluated one step at a time. For training, conceptually unroll the recurrence into T copies of a cell. These are not independent parameters: each copy uses the same W values. Backpropagation through time (BPTT) applies the chain rule backward from later losses through earlier hidden states.

∂Lₜ/∂hₖ contains products of recurrent Jacobians for steps k+1,…,t

For a simple scalar recurrence hₜ=tanh(Whₜ₋₁+Uxₜ), derivative back through one time step contains factor W·tanh′(zₜ). Back through many steps multiplies many such factors. If typical magnitude is below 1, gradients shrink; above 1, they may grow.

Full BPTT vs truncated BPTT

  • Full BPTT: backpropagate through entire sequence; accurate gradient for the chosen unrolled sequence, but memory grows with T.
  • Truncated BPTT: backpropagate through a window of k steps, detach hidden state at boundaries. More memory-efficient but gradients do not credit dependencies beyond the truncation horizon.
  • Streaming state: carry state from one chunk to the next when processing continuous streams; detach it to prevent unbounded graph retention, but do not reset its numeric values unless sequence boundary requires it.

Where the loss is applied

For many-to-one classification, a single loss may be applied to final valid state. For aligned sequence labeling, compute a loss at every valid step and mask padding. For language modeling, shift inputs/targets so output at step t predicts the next token, not the current one. Incorrect alignment can make training appear to run while optimizing the wrong task.

5. Vanishing and exploding gradients

Why gradients vanish

If each recurrent step contributes a derivative factor around 0.5, then after 10 steps the product is 0.5¹⁰≈0.00098. Earlier inputs receive almost no learning signal. Saturating tanh/sigmoid can make their derivatives small as well. The model then learns local dependencies better than long-range relationships.

Why gradients explode

If repeated factors are around 1.2, after 10 steps the product is 1.2¹⁰≈6.19; over more steps it can become enormous. Gradients can cause unstable updates, NaNs, or infinities.

IssueTypical symptomCommon response
Vanishing gradientEarly sequence content has little influence; slow long-term learning.LSTM/GRU gating, residual/skip paths where appropriate, better initialization, shorter horizon or attention.
Exploding gradientSudden huge loss, unstable updates, NaNs.Gradient clipping, lower learning rate, check data and initialization.

Gradient clipping rescales a gradient if its norm exceeds threshold c:

if ||g||₂>c, then g ← g · c/||g||₂

Clipping limits update magnitude; it does not make an architecture remember long dependencies and does not fix wrong data/labels.

Why LSTM helps (careful statement)

An LSTM provides a cell-state path with additive updates controlled by gates. When forget gate values are near 1 and input updates are appropriately gated, information and gradient can pass across many steps more directly than in a vanilla RNN. This mitigates vanishing gradients; it does not guarantee perfect long-term memory or eliminate all optimization difficulties.

6. LSTM in depth: memory, gates, equations

Two kinds of state

  • Cell state cₜ: internal memory pathway that can carry information across time.
  • Hidden state hₜ: exposed representation passed to the next time step and often used for output.

At each step, LSTM uses current input xₜ and previous hidden state hₜ₋₁ to decide what to forget, what to write, and what to expose. Gates are vectors with values in (0,1) from sigmoid; elementwise multiplication makes each dimension's control data-dependent.

All LSTM equations

Let uₜ=[hₜ₋₁,xₜ] be concatenated prior hidden state and current input.

fₜ=σ(Wfuₜ+bf)   (forget gate)
iₜ=σ(Wiuₜ+bi)   (input/write gate)
gₜ=tanh(Wguₜ+bg)   (candidate cell content)
cₜ=fₜ⊙cₜ₋₁+iₜ⊙gₜ   (updated cell state)
oₜ=σ(Wouₜ+bo) ;   hₜ=oₜ⊙tanh(cₜ)   (exposed hidden state)
ComponentRangeIntuitionExtreme interpretation
Forget fₜ(0,1)How much old cₜ₋₁ to retain.0 forget; 1 retain.
Input iₜ(0,1)How much candidate to write.0 write none; 1 write fully.
Candidate gₜ(−1,1)New possible content.May add positive or negative memory.
Output oₜ(0,1)How much cell state to expose.0 hide; 1 expose tanh(cₜ).

Why the additive cell update matters

Vanilla RNN state is repeatedly transformed through nonlinear recurrence. LSTM cell update has a direct additive path fₜ⊙cₜ₋₁ + iₜ⊙gₜ. The derivative along the old-cell path contains fₜ rather than necessarily passing through a saturating tanh at every step. If fₜ is near 1, that path can preserve information/gradient. Gates learn when to retain or overwrite memory.

Forget-gate bias intuition

Because sigmoid(0)=.5, a forget gate with pre-activation 0 initially retains half of the old cell state. A positive forget bias can start the network with stronger retention. The exact initialization depends on framework/version and implementation; do not assume every library uses a particular forget bias unless specified.

Common conceptual mistakes

  • Calling cₜ and hₜ the same state: they are distinct.
  • Using matrix multiplication where ⊙ is intended: gate-state products are elementwise.
  • Claiming forget gate controls new candidate: it scales old cell state.
  • Claiming input gate decides output exposure: output gate controls hₜ exposure.
  • Saying LSTM eliminates vanishing gradient: it mitigates it via a better path, but does not guarantee elimination.

7. RNN and LSTM worked numericals

Numerical A: scalar vanilla RNN, two time steps

Use hₜ=tanh(wxxₜ+whhₜ₋₁+b), h₀=0, wₓ=2, wₕ=.5, b=−1.

  1. At t=1, x₁=1: z₁=2(1)+.5(0)−1=1; h₁=tanh(1)≈.7616.
  2. At t=2, x₂=−1: z₂=2(−1)+.5(.7616)−1=−2.6192; h₂=tanh(−2.6192)≈−.989.

The second step uses h₁, not h₀. Omitting the prior hidden state would turn it into independent per-time-step processing.

Numerical B: LSTM cell update with scalar gates

Given cₜ₋₁=2, fₜ=.8, iₜ=.25, candidate gₜ=−1, oₜ=.5:

cₜ=.8(2)+.25(−1)=1.6−.25=1.35
hₜ=.5·tanh(1.35)≈.5(.8740)=.4370

Interpretation: most old memory survives; a small negative candidate is written; half of transformed cell memory is exposed as hidden output.

Numerical C: identify what each gate does

If f=.1, i=.9, g=.6, cₜ₋₁=4, then cₜ=.1(4)+.9(.6)=.4+.54=.94. The network mostly forgets old content and writes much of the candidate.

Numerical D: vanishing/exploding product

If each recurrent derivative factor magnitude is .8 for 10 steps, product=.8¹⁰≈.1074. At .5 per step, .5¹⁰≈.000977. At 1.2 per step, 1.2¹⁰≈6.192. The exact RNN Jacobian is a matrix, but this scalar product makes the accumulation intuition clear.

Numerical E: sequence tensor shape

Input [B=4,T=12,F=3], one-layer unidirectional LSTM with hidden size H=5 and batch_first=True. Output over all steps is [4,12,5]. Final hidden state h_n is [num_layers×directions=1,4,5]. Final cell state c_n also [1,4,5].

Numerical F: recurrent parameter count

For simple RNN input width I=3, hidden size H=5, one direction, with two PyTorch bias vectors: input weights 5×3=15; recurrent weights 5×5=25; biases 5+5=10; total 50. A theoretical formulation with one combined bias would count 45; PyTorch's standard RNN module has bias_ih and bias_hh, so its actual count is 50.

For PyTorch LSTM, four gate transforms are packed: input weights 4HI, recurrent weights 4H², and two bias vectors of length 4H each. I=3,H=5 gives 60+100+40=200.

8. PyTorch sequence shapes and API

batch_first convention

nn.RNN, nn.LSTM, and nn.GRU default to [T,B,F]. With batch_first=True, input is [B,T,F] and output is [B,T,H×directions]. Hidden states keep layer/direction first even when batch_first is true.

TensorUnidirectional shapeMeaning
Input (batch first)[B,T,F]Batch, time, feature dimensions
RNN/LSTM output[B,T,H]Top-layer hidden output at each time step
h_n[layers×directions,B,H]Final hidden state for each layer/direction
LSTM c_n[layers×directions,B,H]Final cell state (LSTM only)
Bidirectional output[B,T,2H]Forward and backward features concatenated

Important return signatures

# RNN/GRU:
output, h_n = rnn(x)
# LSTM:
output, (h_n, c_n) = lstm(x)

Many bugs come from unpacking LSTM like an RNN. The hidden state h_n and cell state c_n are separate returned tensors. For many-to-one, use final hidden state or gather output at the last valid time. For bidirectional models, carefully combine final forward/backward states; simply taking output[:,−1] does not always represent both directions' terminal states as intended.

Variable-length sequences and padding

Padding to fixed T adds placeholder steps. If you take output[:,−1] for a shorter padded sequence, that may be the padding state rather than its last real state. Options: gather h at length−1 for a unidirectional model; use pack_padded_sequence; use masks in pooling/loss; bucket examples by length. For bidirectional RNNs, packing is especially important so backward direction does not process padding as real context.

State reset

For independent sequences, start from default zero state each batch unless passing state explicitly. For contiguous chunks of one long stream, carrying state can be intentional; detach state between chunks during truncated BPTT to avoid retaining the entire graph.

9. RNN, LSTM, GRU parameter counts

Single-layer unidirectional simple RNN

PyTorch with bias: H·I + H·H + 2H = H(I+H+2)

PyTorch parameter names include weight_ih_l0 [H,I], weight_hh_l0 [H,H], bias_ih_l0 [H], bias_hh_l0 [H]. If bias=False, drop the 2H term.

Single-layer unidirectional LSTM

4HI + 4H² + 8H = 4H(I+H+2)

Why factor 4? There are input gate, forget gate, candidate, and output gate affine transforms. PyTorch packs their rows into matrices with 4H rows and has two bias vectors of length 4H. The master notes write the four gate equations separately; implementation may combine them for efficiency.

GRU rough formula

GRU has three gate/candidate transforms, so PyTorch one-layer, one-direction count with bias is approximately 3HI+3H²+6H. Exact formulation varies slightly across libraries and reset-after conventions.

Stacked and bidirectional

For a second stacked layer, its input width is H for unidirectional, 2H for bidirectional. Bidirectional output width doubles. Count each layer and each direction; include both direction parameter sets. Add any projection/classifier head separately.

Worked LSTM parameter example

I=10 features, H=32, one direction, bias=True: input weights=4×32×10=1,280; recurrent weights=4×32×32=4,096; biases=8×32=256. Total=5,632. A linear 32→3 head adds 32×3+3=99; total model params=5,731.

10. RNN vs LSTM vs GRU

PropertyVanilla RNNLSTMGRU
StateHidden hHidden h and cell cHidden h (no separate cell)
Gate structureNoneForget, input, output plus candidateReset and update plus candidate
ParametersLowestMore; four affine componentsUsually between RNN and LSTM
Long dependenciesOften difficult due to gradient pathDesigned to preserve/update memory selectivelyGates provide controlled memory update
Typical useShort/simple sequences, baselineLonger temporal dependencies where usefulSimpler gated alternative

No cell is universally best. LSTM is often a good conceptual model for gated memory; GRU can be simpler and competitive; vanilla RNN is useful for understanding recurrence. Compare validation performance and compute for the actual task.

Bidirectional RNNs

A bidirectional model runs one recurrent pass forward and another backward, concatenating representations. It can use future context when producing a representation for a token, useful in offline tagging/encoding. It is not directly causal for real-time forecasting or autoregressive generation because the backward pass sees future inputs.

When attention/transformers enter

RNNs process sequentially and pass state forward; attention lets positions directly interact. Transformers are covered later in the syllabus. Knowing RNNs provides a clear contrast: recurrent state is a compressed sequential summary, while self-attention computes content-dependent interactions across positions.

11. Small code patterns between concepts

Define and call an LSTM

lstm = torch.nn.LSTM(
    input_size=10, hidden_size=32,
    num_layers=1, batch_first=True
)
x = torch.randn(8, 12, 10)       # [B=8,T=12,F=10]
output, (h_n, c_n) = lstm(x)
print(output.shape)  # [8,12,32]
print(h_n.shape)     # [1,8,32]
print(c_n.shape)     # [1,8,32]

Many-to-one head

last_hidden = h_n[-1]        # [B,H] for one-way, one-layer LSTM
logits = classifier(last_hidden)  # [B,num_classes]

For bidirectional networks, h_n has two directions; concatenate final forward/backward states for sequence classification.

Clip exploding gradients

loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()

Clip after backward has computed gradients and before applying update. It limits norm, not every gradient coordinate independently.

Mask padded positions in loss

# logits: [B,T,C], labels: [B,T], pad label = -100
loss = torch.nn.functional.cross_entropy(
    logits.reshape(-1, num_classes),
    labels.reshape(-1),
    ignore_index=-100
)

PyTorch's ignore_index prevents padded target positions from contributing to loss. The model still needs a sensible recurrent handling of padding; masking the loss alone does not prevent padding from affecting hidden state.

13. Practice questions with worked solutions

Q1. For hₜ=tanh(2xₜ+0.5hₜ₋₁−1), h₀=0 and x₁=1, find h₁.

z₁=2(1)+.5(0)−1=1; h₁=tanh(1)≈.7616.

Q2. Continue Q1 with x₂=−1. Find h₂ approximately.

z₂=−2+.5(.7616)−1=−2.6192; tanh(z₂)≈−.989.

Q3. cₜ₋₁=2, f=.8, i=.25, candidate=−1, o=.5. Find cₜ and hₜ.

cₜ=1.6−.25=1.35. hₜ=.5 tanh(1.35)≈.437.

Q4. Which LSTM gate retains old cell state?

Forget gate fₜ; it multiplies cₜ₋₁.

Q5. Input [B=6,T=20,F=4] into batch_first LSTM with hidden=12, one direction. Output and h_n shapes?

output [6,20,12]; h_n [1,6,12]. LSTM c_n also [1,6,12].

Q6. Same model but bidirectional. Output shape?

[6,20,24] because forward/backward features concatenate; h_n has shape [2,6,12].

Q7. PyTorch LSTM I=3,H=5, one layer one direction with bias. Count params.

4HI+4H²+8H=60+100+40=200.

Q8. A .7 gradient factor is multiplied across 8 recurrent steps. Approximate product.

.7⁸≈.05765; the gradient shrinks substantially.

Q9. What is wrong with using output[:,−1] for every sequence when examples have different padded lengths?

For shorter examples the last index may correspond to padding, not the last valid time step. Gather by length, pack sequences, or mask appropriately.

Q10. Is a bidirectional LSTM appropriate for real-time next-step forecasting?

Usually not if its backward direction consumes future observations unavailable at prediction time; it causes information leakage.

Q11. Does gradient clipping solve vanishing gradients?

No. It limits exploding gradients; LSTM/GRU structure and other methods address vanishing more directly.

Q12. Distinguish LSTM output, h_n, and c_n.

output gives top-layer hidden representation at every time step; h_n gives final hidden state per layer/direction; c_n gives final cell state per layer/direction.

15. Complete PyTorch example at the end: classify sequences with an LSTM

This runnable teaching example generates fixed-length univariate sequences. Class 0 tends to trend down, class 1 tends to trend up. An LSTM encodes the ordered sequence, and a linear head classifies it. It demonstrates batch/time/feature shapes, train/validation split, logits with cross-entropy, clipping, and correct evaluation behavior.

import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader, random_split

# ------------------------------------------------------------
# 1) Make reproducible synthetic sequences
# ------------------------------------------------------------
torch.manual_seed(11)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

n_examples = 1200
sequence_length = 20
num_features = 1
num_classes = 2

# A shared time axis. Class 0 has a negative slope; class 1 positive.
t = torch.linspace(-1.0, 1.0, sequence_length).view(1, sequence_length, 1)
labels = torch.randint(0, 2, (n_examples,))
slopes = torch.where(labels == 1, 1.0, -1.0).view(n_examples, 1, 1)
noise = 0.25 * torch.randn(n_examples, sequence_length, 1)
sequences = slopes * t + noise  # [N,T,F]

dataset = TensorDataset(sequences, labels)
train_ds, val_ds = random_split(
    dataset, [960, 240],
    generator=torch.Generator().manual_seed(11)
)
train_loader = DataLoader(train_ds, batch_size=48, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=96, shuffle=False)

# ------------------------------------------------------------
# 2) Define an LSTM sequence classifier
# ------------------------------------------------------------
class SequenceClassifier(nn.Module):
    def __init__(self, input_size, hidden_size, classes):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size=input_size,
            hidden_size=hidden_size,
            num_layers=1,
            batch_first=True
        )
        self.classifier = nn.Linear(hidden_size, classes)

    def forward(self, x):
        # x: [B,T,F]
        output, (h_n, c_n) = self.lstm(x)
        # For one layer, one direction, h_n is [1,B,H].
        final_hidden = h_n[-1]       # [B,H]
        logits = self.classifier(final_hidden)  # [B,C]
        return logits

hidden_size = 16
model = SequenceClassifier(
    input_size=num_features,
    hidden_size=hidden_size,
    classes=num_classes
).to(device)

# PyTorch LSTM count for I=1,H=16:
# 4*H*I + 4*H*H + 8*H = 64 + 1024 + 128 = 1216
# Classifier 16*2+2 = 34; total = 1250.
print("trainable parameters:",
      sum(p.numel() for p in model.parameters() if p.requires_grad))

criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-2)

# ------------------------------------------------------------
# 3) Train: clear -> forward -> loss -> backward -> clip -> step
# ------------------------------------------------------------
for epoch in range(15):
    model.train()
    train_loss_sum, train_correct, train_count = 0.0, 0, 0

    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)

        optimizer.zero_grad()
        logits = model(xb)              # [B,2]
        loss = criterion(logits, yb)    # raw logits + integer labels
        loss.backward()

        # Limit unusually large gradient norm before parameter update.
        nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()

        batch_size = yb.size(0)
        train_loss_sum += loss.item() * batch_size
        train_correct += (logits.argmax(dim=1) == yb).sum().item()
        train_count += batch_size

    train_loss = train_loss_sum / train_count
    train_accuracy = train_correct / train_count

    # --------------------------------------------------------
    # 4) Validation: no gradient graph and no parameter update
    # --------------------------------------------------------
    model.eval()
    val_loss_sum, val_correct, val_count = 0.0, 0, 0
    with torch.no_grad():
        for xb, yb in val_loader:
            xb, yb = xb.to(device), yb.to(device)
            logits = model(xb)
            loss = criterion(logits, yb)
            batch_size = yb.size(0)
            val_loss_sum += loss.item() * batch_size
            val_correct += (logits.argmax(dim=1) == yb).sum().item()
            val_count += batch_size

    val_loss = val_loss_sum / val_count
    val_accuracy = val_correct / val_count
    print(
        f"epoch {epoch + 1:02d} | "
        f"train loss={train_loss:.3f}, acc={train_accuracy:.3f} | "
        f"val loss={val_loss:.3f}, acc={val_accuracy:.3f}"
    )

# ------------------------------------------------------------
# 5) Predict one sequence
# ------------------------------------------------------------
example = sequences[:1].to(device)  # [1,T,F]
model.eval()
with torch.no_grad():
    logits = model(example)                 # [1,2]
    probabilities = logits.softmax(dim=1)  # optional
    predicted_class = logits.argmax(dim=1)

print("logits:", logits)
print("probabilities:", probabilities)
print("predicted class:", predicted_class.item())

Walkthrough

  1. Sequence construction: every example has T=20 ordered scalar observations; feature width F=1. Labels are integer class IDs 0/1.
  2. Batch shape: a batch is [B,20,1]. The batch_first option makes this convention explicit.
  3. LSTM output: output is [B,T,H], while h_n and c_n are [1,B,H] for one layer/direction.
  4. Many-to-one head: h_n[-1] selects final hidden state for the top layer; classifier maps H=16 to C=2 logits.
  5. Parameter count: LSTM has 1,216 parameters; head has 34; total 1,250.
  6. Loss: CrossEntropyLoss receives [B,2] logits and [B] long labels.
  7. Update sequence: zero_grad, forward, loss, backward, clipping, step. Clipping is applied after gradients exist.
  8. Validation: eval plus no_grad. No optimizer step occurs.
  9. Inference: logits rank classes; softmax is included only to show probabilities.
Shape audit: [B,20,1] → LSTM output [B,20,16], h_n [1,B,16], c_n [1,B,16] → final h [B,16] → classifier logits [B,2].
