1. Encoder, decoder, and encoder-decoder models

1.1 Encoder-only: BERT-like representations

An encoder applies bidirectional self-attention to the available input tokens: a token representation can use left and right context. BERT’s original pretraining uses masked language modeling (MLM), predicting selected masked tokens from context; the original also used next sentence prediction (NSP), while later encoder models may change or omit NSP. BERT is a model family/architecture, not one downstream task.

Common tasks: sentence classification (often a pooled/CLS representation plus a classifier), token classification such as NER (one output per token), extractive QA (start/end scores), and sentence-pair classification. For token tasks, special tokens and padded positions require label alignment/masking.

1.2 Decoder-only: GPT-like generation

A decoder-only stack uses causal self-attention: position t sees only positions ≤t. It is commonly pretrained with next-token/causal language modeling, maximizing Σtlog p(xt|x<t). The same model can generate by repeatedly feeding prior tokens plus newly generated tokens. Instruction tuning can teach it to follow tasks, but it remains a probabilistic text generator and can produce unsupported claims.

1.3 Encoder-decoder: translation and conditional generation

An encoder reads the source bidirectionally and produces memory H. A causal decoder predicts the target sequence. Its cross-attention has Q from decoder states and K,V from H. Training teacher-forces shifted target tokens; at inference, it generates until EOS or a length limit. Tasks include translation, summarization, and conditional generation.

Encoder-onlyBidirectional within inputNoMasked token prediction; classification/NER/QA

1.4 BERT vs GPT: common distractors

  • BERT-style encoder is not inherently a left-to-right generator; its bidirectional pretraining makes direct autoregressive decoding a different objective.
  • GPT-style decoder is not trained to use future target tokens at a position; its causal mask blocks them.
  • Encoder-decoder is not “BERT then GPT” in a loose sense only: the decoder has cross-attention layers that explicitly read encoder representations.
  • Masked language modeling and causal language modeling are distinct prediction setups.
  • Pretraining objective and downstream architecture/task are related but not synonymous.

2. Sequence-to-sequence learning and translation

2.1 Shifted targets and teacher forcing

For source “I like cats” and target “J’aime les chats”, the decoder input is usually [BOS, J’aime, les, chats], while labels are [J’aime, les, chats, EOS]. Teacher forcing uses the gold previous target token as decoder input during training. The cross-entropy loss sums/averages next-token likelihoods over non-padding target positions.

LNLL=−Σt log pθ(yt|y<t,x)

At inference no gold target is available: greedy decoding, beam search, or sampling selects a token, then feeds it into the next step. A model can show exposure bias because it trains on gold prefixes but at test time conditions on its own imperfect outputs.

2.2 Translation evaluation

Exact match is usually too strict for translation. BLEU estimates n-gram precision with a brevity penalty; chrF uses character n-gram overlap; COMET uses learned semantic evaluation. Metrics correlate imperfectly with human quality and should be paired with human review. Keep source references and tokenization protocol consistent when comparing scores.

2.3 Numerical: translation token loss

Suppose target probabilities at three unpadded positions are .5, .25, and .8. Total NLL=−ln(.5)−ln(.25)−ln(.8)=.6931+1.3863+.2231=2.3025 nats. Mean token NLL=.7675; perplexity=exp(.7675)≈2.154. If one padded position is present, it must be ignored by the loss mask.

# Decoder inputs and labels are shifted by one token.
decoder_input_ids = target_ids[:, :-1]
labels = target_ids[:, 1:].clone()
labels[labels == PAD_ID] = -100  # common HF ignore index
outputs = model(input_ids=source_ids,
                attention_mask=source_mask,
                decoder_input_ids=decoder_input_ids,
                labels=labels)
loss = outputs.loss

Some sequence-to-sequence APIs shift labels internally when labels are provided; do not shift twice. Check the model’s documented input contract.

3. Fine-tuning pretrained language models

3.1 Transfer learning workflow

  1. Pick a pretrained checkpoint compatible with task and language.
  2. Use its own tokenizer and special tokens; truncate/pad to a justified maximum length.
  3. Choose a task head/model class and target labels.
  4. Create train/validation/test splits with no leakage (group/user/time-aware as needed).
  5. Fine-tune on train; use validation for hyperparameters/early stopping; keep test held out.
  6. Save tokenizer, task/config, label mapping, and weights/adapters together.

Full fine-tuning updates all model parameters. It can adapt flexibly but needs more optimizer-state memory, compute, and storage. Frozen feature extraction trains only a head. PEFT trains a small subset of parameters while most base weights remain frozen.

3.3 LoRA equations and parameter math

For W∈Rdout×din, approximate an update ΔW with B∈Rdout×r and A∈Rr×din. Then W′=W+(α/r)BA. Trainable params are r(dout+din) instead of doutdin. The scaling factor α/r affects update magnitude, not parameter count.

For a 768×768 projection and r=8: full matrix=589,824. LoRA adds 8(768+768)=12,288, or 2.083% of that matrix. For separate Q and V matrices in each of 12 layers, count 12×2×12,288=294,912 adapter weights. Compare this with 12×2×589,824=14,155,776 base projection weights. Exact total-model ratio depends on what other layers are adapted/unfrozen.

3.4 Small code: attach LoRA to a BERT classifier

from transformers import AutoModelForSequenceClassification
from peft import LoraConfig, TaskType, get_peft_model

base = AutoModelForSequenceClassification.from_pretrained(
    "bert-base-uncased", num_labels=2
)
config = LoraConfig(
    task_type=TaskType.SEQ_CLS, r=8, lora_alpha=16,
    lora_dropout=0.05, target_modules=["query", "value"],
    modules_to_save=["classifier"]
)
model = get_peft_model(base, config)
model.print_trainable_parameters()

Target module names are architecture-specific. Inspect model.named_modules() if adaptation misses layers, and check trainable parameter count rather than assuming the config matched.

3.5 Prompt engineering vs prompt tuning vs fine-tuning

  • Prompt engineering: manually write a discrete text instruction; no weights are trained.
  • Prompt tuning: optimize continuous virtual-token embeddings; typically freeze base model.
  • Fine-tuning: update all or selected model weights from examples.
  • RAG: retrieve external evidence and place it in context at inference; retrieval changes available evidence, not base weights.

“Prompt fine-tuning” can be ambiguous in informal use; state whether you mean learned soft prompts (prompt tuning) or supervised fine-tuning on prompt/response examples.

4. Worked numericals and exam-style code patterns

Numerical A: LoRA parameter count and percentage

For din=dout=1024, r=4: trainable low-rank params=4(1024+1024)=8,192; full dense matrix=1,048,576. Percentage=8,192/1,048,576×100=0.78125%. If both Q and V are adapted in 24 layers, multiply each figure by 48.

Numerical B: one-head cross-attention shapes

Encoder memory [B=2,S=10,d=64], decoder states [2,T=6,64], 4 heads. Per-head width=16. Decoder query [2,4,6,16], encoder keys/values [2,4,10,16], cross-attention scores [2,4,6,10], output [2,6,64] after concatenation/projection.

Numerical C: generation budget

Prompt has 160 tokens and generation cap 96 tokens. At most 256 tokens are processed in a simple no-cache accounting of full prompt plus output; with KV cache, prompt is prefetched and each new token adds one position to each layer’s cache. Context limit must cover both prompt and generated tokens.

5. Exam-style practice with worked answers

Q1. BERT-like encoder or GPT-like decoder for token classification using both left and right context?

An encoder-only bidirectional model is the typical choice. A task-specific head predicts a tag at each token, with padding labels ignored.

Q2. For LoRA on one 768×768 matrix at rank 8, how many additional parameters?

8(768+768)=12,288.

Q3. For translation, what is decoder cross-attention Q versus K,V?

Q comes from current decoder hidden states; K and V come from the encoder’s source representations.

Q4. A causal model uses target sequence length 5. What is the attention score shape per batch/head?

[5,5]. The causal mask blocks the strict upper triangle (future keys) before softmax.

Q5. If labels are padding IDs, should they contribute to sequence cross-entropy?

No. Set ignored label positions (commonly −100 in Hugging Face/PyTorch loss contracts) or multiply by a validity mask.

Q6. Does prompt engineering update any learned parameter?

No. It changes discrete input text. Prompt tuning learns continuous virtual-token embeddings; fine-tuning changes model parameters.

6. Complete end-of-week program: LoRA fine-tune a BERT classifier

This compact example tokenizes labeled text, attaches LoRA to BERT query/value projections, performs a manual PyTorch training loop, evaluates on a held-out set, and saves adapter/tokenizer artifacts. The tiny demonstration data is only for code flow; use a real balanced dataset and validation protocol in actual work.

"""Week 11 lab: PEFT LoRA for binary text classification."""
import torch
from torch.utils.data import DataLoader, TensorDataset
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from peft import LoraConfig, TaskType, get_peft_model

SEED = 53
torch.manual_seed(SEED)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model_id = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_id)

# Toy examples only. Replace with a real, audited labeled corpus.
texts = [
    "The explanation was clear and useful.",
    "I enjoyed the examples and learned a lot.",
    "This guide is concise and accurate.",
    "The result was excellent and easy to follow.",
    "The answer was confusing and incomplete.",
    "I disliked the examples and found errors.",
    "This guide is unclear and unhelpful.",
    "The result was poor and hard to follow.",
    "A helpful explanation with a good example.",
    "A disappointing answer with missing details.",
]
labels = torch.tensor([1,1,1,1,0,0,0,0,1,0], dtype=torch.long)
encoded = tokenizer(texts, padding=True, truncation=True, max_length=64,
                    return_tensors="pt")

# Deterministic train/test split; realistic work needs more data and validation.
train_idx = torch.tensor([0,1,2,4,5,6,8,9])
test_idx = torch.tensor([3,7])
train_ds = TensorDataset(encoded["input_ids"][train_idx],
                         encoded["attention_mask"][train_idx],
                         labels[train_idx])
train_loader = DataLoader(train_ds, batch_size=4, shuffle=True)

base = AutoModelForSequenceClassification.from_pretrained(
    model_id, num_labels=2
)
peft_config = LoraConfig(
    task_type=TaskType.SEQ_CLS,
    r=4,
    lora_alpha=8,
    lora_dropout=0.05,
    target_modules=["query", "value"],  # BERT module names
    modules_to_save=["classifier"]     # keep task head trainable/saved
)
model = get_peft_model(base, peft_config).to(device)
model.print_trainable_parameters()
optimizer = torch.optim.AdamW(
    [p for p in model.parameters() if p.requires_grad], lr=2e-4
)

for epoch in range(3):
    model.train()
    total_loss = 0.0
    for input_ids, attention_mask, y in train_loader:
        batch = {
            "input_ids": input_ids.to(device),
            "attention_mask": attention_mask.to(device),
            "labels": y.to(device)
        }
        optimizer.zero_grad(set_to_none=True)
        outputs = model(**batch)        # outputs.loss and logits [B,2]
        outputs.loss.backward()
        torch.nn.utils.clip_grad_norm_(
            (p for p in model.parameters() if p.requires_grad), 1.0
        )
        optimizer.step()
        total_loss += outputs.loss.item()
    print(f"epoch {epoch+1}: mean batch loss="
          f"{total_loss/len(train_loader):.3f}")

model.eval()
with torch.no_grad():
    logits = model(
        input_ids=encoded["input_ids"][test_idx].to(device),
        attention_mask=encoded["attention_mask"][test_idx].to(device)
    ).logits
predictions = logits.argmax(dim=-1).cpu()
print("test predictions:", predictions.tolist())
print("test labels:", labels[test_idx].tolist())

# Save adapter (not a duplicate full base model) and its tokenizer.
model.save_pretrained("week11_bert_lora_adapter")
tokenizer.save_pretrained("week11_bert_lora_adapter")

Walkthrough and correctness checks

  1. Tokenizer contract: the same BERT tokenizer generates input IDs and attention mask; padding positions are marked by mask 0.
  2. Task head: sequence classifier returns two logits per input; labels are integer IDs 0/1 and are passed to the model loss.
  3. PEFT setup: query/value module names match BERT’s attention projections; classifier is included in modules_to_save.
  4. Optimizer: only parameters with requires_grad=True are passed, reducing optimizer state.
  5. Validation: eval and no_grad turn off training behavior and autograd tracking; neither is a substitute for the other.
  6. Artifact: PEFT save stores adapter configuration/weights; inference also needs the compatible base model. Checkpoint includes label mapping in real tasks.
Limitations: the ten toy rows are not a meaningful benchmark; use a stratified/group-aware train-validation-test split, enough examples, label quality checks, early stopping, and suitable metrics. BERT download needs network access; model/code APIs change over time, so check linked official PEFT docs.

7. Week 11 formula card and references

Architecture masks

BERT encoder: bidirectional; GPT decoder: causal; seq2seq decoder: causal self-attention plus cross-attention.

Conditional NLL

−Σtlog p(yt|y<t,x), ignoring PAD labels.

LoRA parameters

r(din+dout) per adapted dense projection.

Training diagnosis

Trainable params, loss-label contract, masks, gradient path, held-out validation.

  • Can I choose an encoder, decoder, or encoder-decoder from the task?
  • Can I derive masked vs causal attention visibility?
  • Can I shift target sequences correctly and exclude padding?
  • Can I calculate LoRA count and compare it with full-matrix parameters?
  • Can I distinguish discrete prompts, soft prompts, LoRA, full tuning, and RAG?
