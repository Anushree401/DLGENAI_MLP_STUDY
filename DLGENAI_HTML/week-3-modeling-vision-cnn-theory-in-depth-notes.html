How to use these notes

Week 3 introduces convolutional neural networks: architecture basics, convolution, and pooling. Week 4 is hands-on image classification, so this guide emphasizes the theory behind tensor dimensions and CNN design. The quiz papers repeatedly test CNN parameter arithmetic and output shapes through short MCQs and connected numerical questions.

Highest-yield patterns from the supplied Quiz 1 materials: Conv2d parameter counts (including or excluding bias), output shapes after convolution/pooling, receptive-field size, SAME padding, channel concatenation in Inception, 1×1 convolution, GAP versus flatten, and reading PyTorch Conv2d argument order. The exam notes rank CNN parameter counting as a top recurring topic.

Use this order: understand a filter as a local dot product shared over positions; calculate height/width output shape; count learned weights; then reason about what pooling/stacking does to spatial resolution and receptive field. Keep channels separate from spatial dimensions throughout.

Notation alert: drawings often write image shape as H×W×C, while PyTorch tensors use N×C×H×W (batch, channels, height, width). A quiz question may state H×W×C as a human-readable volume; convert to PyTorch order when writing code.

1. Why CNNs for images?

Images have spatial structure

An image is not just a long list of independent numbers. Nearby pixels often belong to the same edge, texture, or object part; the same feature can appear at different locations. A fully connected layer ignores this geometry and gives every output its own weight for every pixel. A convolutional layer instead uses a small local filter and reuses its weights across positions.

Local connectivity

A unit looks at a small receptive patch, such as 3×3 pixels, rather than the entire image.

Weight sharing

One filter is reused at every spatial location. “A vertical edge” can be detected anywhere with the same learned pattern.

Translation equivariance

Shifting an input tends to shift the feature map correspondingly (away from boundaries); the representation changes predictably with location.

Hierarchical features

Early filters often respond to edges/textures; deeper layers combine them into larger parts and patterns.

Convolution does not guarantee translation invariance: it is typically equivariant. Pooling, global pooling, augmentation, and later layers may provide some tolerance to location changes, but exact invariance is not automatic.

2. Image tensors: height, width, channels

A grayscale image has one channel; an RGB image has three; an intermediate CNN feature map can have dozens or hundreds. A CNN layer does not usually process a single 2D plane when there are multiple input channels: every filter spans the full input depth.

ConventionImage / batch shapeExample: batch of RGB 32×32 images
Human / many diagramsH×W×C or N×H×W×C (NHWC)32×32×3 or [B,32,32,3]
PyTorch Conv2dN×C×H×W (NCHW)[B,3,32,32]

For PyTorch, nn.Conv2d(in_channels, out_channels, ...) must receive input with channel dimension at index 1. A grayscale mini-batch is [B,1,H,W]. The first Conv2d argument is input channels; the second is number of learned output filters. Swapping them is a common exam mistake.

# A batch of 16 grayscale 28x28 images
x.shape == (16, 1, 28, 28)

conv = torch.nn.Conv2d(
    in_channels=1,   # input image has one channel
    out_channels=8,  # learn 8 distinct filters
    kernel_size=3,
    stride=1,
    padding=1
)
y = conv(x)
print(y.shape)       # [16, 8, 28, 28]
Paper pattern: a question says an image/feature map contains 16 channels and asks which Conv2d code is correct. Use nn.Conv2d(16, out_channels, ...). First argument is in_channels, not number of filters.

3. Convolution step by step

A filter is a learned local template

For one input channel and stride 1, a 3×3 filter is placed over a 3×3 patch. Multiply corresponding entries, sum, add bias. Move it to the next location and repeat. The same 9 weights are reused at each location.

Y[i,j] = Σu=0K−1 Σv=0K−1 X[i+u,j+v]K[u,v] + b

Deep-learning libraries commonly implement cross-correlation (kernel not flipped) but call it convolution. Since filter weights are learned, the naming distinction does not change the layer's expressive ability or parameter count. For exam arithmetic, multiply the aligned patch values and kernel values.

Numerical 3×3 filter on a small image

Input X=[[1,2,0],[0,1,3],[2,1,0]], kernel K=[[1,0],[0,−1]], stride 1, no padding, no bias. Output has shape 2×2. Top-left patch [[1,2],[0,1]] gives 1·1+2·0+0·0+1·(−1)=0. Top-right patch [[2,0],[1,3]] gives 2+0+0−3=−1. Bottom-left [[0,1],[2,1]] gives 0−1=−1. Bottom-right [[1,3],[1,0]] gives 1. Result [[0,−1],[−1,1]].

This concrete operation illustrates what one filter response means. A learned kernel can produce large positive responses for a pattern, small responses for unrelated patches, and negative responses for opposite patterns.

Multiple channels and multiple filters

Suppose input has Cin channels and layer has Cout filters. One output filter has a separate K×K weight slice for each input channel; those channelwise responses are summed (then bias added) to form one output channel. Thus each filter has K×K×Cin weights. Cout filters produce Cout feature maps.

4. Convolution output shape: the essential formula

For one spatial axis (height or width), input size I, kernel K, padding P, stride S, dilation D:

O = floor((I + 2P − D(K−1) − 1)/S) + 1

For standard dilation D=1 this becomes O=floor((I+2P−K)/S)+1. Apply separately to height and width, since they may differ. Output channel count is Cout.

How to interpret each setting

  • Kernel K: local receptive patch size (e.g. 3×3).
  • Padding P: number of zeros added to each side per spatial axis.
  • Stride S: step between adjacent filter placements.
  • Dilation D: spacing between kernel elements; effective kernel width is K_eff=D(K−1)+1.
  • Floor: if the filter does not fit an extra full step, leftover border pixels may be unused.

Worked examples

Input / settingsCalculationOutput per axis
I=32,K=3,P=0,S=1floor((32−3)/1)+130 (VALID)
I=32,K=3,P=1,S=1floor((32+2−3)/1)+132 (preserved)
I=32,K=5,P=2,S=1floor((32+4−5)/1)+132 (preserved)
I=32,K=3,P=0,S=2floor((32−3)/2)+115
I=31,K=3,P=1,S=2floor((31+2−3)/2)+116
I=28,K=3,P=0,S=1,D=2K_eff=5; floor((28−5)/1)+124

Shape preservation does not imply no computation: padding creates border values (often zeros) so a stride-1 convolution can produce the original spatial size.

5. SAME, VALID, stride and padding

VALID

VALID means no padding: P=0. With stride 1 and odd kernel K, output shrinks by K−1. Example I=32,K=3 gives 30; then another 3×3 VALID convolution gives 28.

SAME

SAME padding aims for output spatial size ceil(I/S). When stride is 1 and kernel is odd, symmetric padding P=(K−1)/2 preserves size. For a 5×5 filter P=2; for 3×3 P=1. These are exactly the independent cases used in the March papers.

Do not overgeneralize: with even kernels or stride greater than one, SAME may require asymmetric padding. “P=K//2” is a handy rule only for stride 1 odd kernels. Use the general output formula when in doubt.

Stride trades resolution for computation

Stride 2 moves the kernel two positions at a time and reduces spatial resolution roughly by half. This lowers compute and increases spacing between sampled positions, but loses precise location detail. Stacking stride-2 layers compounds downsampling.

Padding is not learned

Zero padding adds fixed values, not trainable parameters. Changing padding changes output dimensions and boundary context, but not Conv2d's learned parameter count.

6. CNN parameter counting, carefully

Convolution layer

Conv2d params = KhKwCinCout + Cout (if bias=True)

Each output filter has KhKwCin weights and usually one bias. Thus increasing image height/width changes the number of applications, not number of filter weights. Increasing input channels or output filters does increase parameter count.

Dense layer after flatten

Linear params = ninnout + nout (if bias=True)

A dense classifier applied after flattening often dominates model parameters because its input dimension is H×W×C. Pooling, ReLU, sigmoid, flatten, and dropout usually have zero learned parameters. BatchNorm commonly has two learned values per normalized channel (scale γ and shift β), though running statistics are stored too but are not learned parameters.

Layer / operationTrainable parameters?Remember

LinearYesInput features × output features, plus optional bias.
MaxPool / AvgPoolNoFixed reduction over local windows.
ReLU / sigmoidNoFixed elementwise function.
FlattenNoReshape only.
DropoutNoRandom mask in training; no learned weights.
BatchNormUsually 2×Cγ and β per normalized channel/feature.

Batch normalization in CNNs

For a feature map [N,C,H,W], BatchNorm2d normalizes each channel using statistics computed across batch and spatial positions during training, then applies learned scale γ and shift β for each channel: y=γ(x−μ)/√(σ²+ε)+β. That gives 2C trainable parameters (γ and β per channel). Running mean and variance are tracked for evaluation but are not trainable weights. For C=64, learnable parameters=128. In training mode it uses current batch statistics; in eval mode it uses stored running statistics. This exact count/mode distinction appears in the supplied quiz material.

Worked parameter count: two convolution layers and classifier

Input 32×32×3. Conv1 has 16 filters of 3×3 with bias: 3×3×3×16+16=448. If padding=1,stride=1, output 32×32×16. 2×2 pool gives 16×16×16. Conv2 has 32 filters of 3×3 with bias: 3×3×16×32+32=4,640. Same padding keeps 16×16; then pool gives 8×8×32. Flatten has 2,048 elements. Dense 2,048→128: 262,144+128=262,272. Dense 128→10: 1,280+10=1,290. Total=268,650 parameters.

Notice spatial size appears only when counting the fully connected layer after flatten. Convolution parameter count does not depend on how many spatial locations the kernel visits.

Compare dense vs convolution on a 10×10 grayscale image

Five-class model A: flatten 10×10×1=100 inputs, Dense(5), no bias =100×5=500 weights. Model B: five 10×10 filters spanning 1 channel, no bias =10×10×1×5=500 weights. Parameter counts are equal in this constructed case, though the convolution applies a spatially structured weight-sharing pattern and outputs locations (here each full-image filter yields one scalar if VALID, stride 1).

7. Pooling and downsampling

Max pooling

MaxPool takes the maximum in each local window independently per channel. It has no learned weights. A 2×2 kernel with stride 2 halves H and W when dimensions divide evenly. It preserves channel count.

Average pooling

AveragePool replaces a window with its mean. It smooths rather than selecting the strongest feature. Both pooling types reduce spatial dimensions; neither mixes channels in standard 2D pooling.

Shape trace: pooling then 1×1 convolution

Start with 6×6×2. MaxPool 2×2 stride 2 gives 3×3×2. A 1×1 convolution with four filters sees the two input channels at each position and creates four output channels: 3×3×4. This exact shape sequence appears in the March quiz papers.

Pooling trap: MaxPool(2,stride=2) changes feature-map shape but has zero trainable parameters. Do not confuse output channels with number of spatial windows.

8. Receptive field: how much of the input can affect one activation?

The receptive field of one feature at layer ℓ is the region of the original input that can influence it. It grows as layers combine neighboring features. For stride-1 convolutions with no dilation, each K×K layer grows the side length by K−1.

For stride-1 K×K convolutions: R₀=1 ; Rₗ=Rₗ₋₁+(Kₗ−1)

Thus n consecutive 3×3 convolutions have receptive field 1+n(3−1): after one it is 3×3, after two 5×5, after three 7×7.

General formula with strides and dilation

Track two quantities: receptive field R and jump J, the spacing in original-input pixels between adjacent features at current layer. Initialize R₀=1, J₀=1. For layer ℓ with kernel Kℓ, stride Sℓ, dilation Dℓ:

Rₗ = Rₗ₋₁ + (Kℓ−1)Dℓ Jₗ₋₁ ;   Jₗ = Jₗ₋₁ Sℓ

This recurrence applies separately to height and width. Pooling also counts as a layer with its own kernel and stride. Padding shifts boundary alignment but does not change this nominal receptive field size.

Numerical examples

  • Three 3×3 convs, each stride 1: 1→3→5→7; receptive field 7×7.
  • Two 3×3 convs stride 1 then 2×2 pool stride 2: first conv R=3,J=1; second R=5,J=1; pool R=6,J=2. Adjacent pooled features correspond to input regions spaced 2 pixels apart.
  • Two 3×3 convs, first stride 2, second stride 1: after first R=3,J=2; second R=3+(2×2)=7,J=2.
Quiz pattern: the March papers ask for receptive field after three consecutive 3×3 stride-1 convolutions; July asks the same. The answer is 7×7, not 9×9: count the initial one-pixel location and add two per layer.

9. Channel-changing blocks, 1×1 convolution, Inception, GAP

1×1 convolution

A 1×1 kernel does not combine neighboring spatial locations. At each (h,w), it takes the vector of Cin channel values and computes a learned linear combination. With Cout filters, it changes depth Cin→Cout while preserving H,W when stride 1 (and no padding is needed).

Parameters: 1×1×C_in×C_out (+C_out bias). It can reduce channels before an expensive convolution, expand channels, or mix channel features. It does not enlarge the spatial receptive field.

Inception-style parallel paths

Branches process the same input with different operations/kernels, then concatenate feature maps along the channel dimension. To concatenate directly, branch outputs must agree in batch, height, and width. Output channels are the sum of branch channel counts.

[28×28×64] ⊕ [28×28×128] ⊕ [28×28×32] ⊕ [28×28×32] = 28×28×256

It is not 112×28×128: concatenation stacks channels; it does not multiply spatial height or width. This is an explicit March-paper question pattern.

Global average pooling (GAP) versus flatten

GAP averages each channel's full spatial map into one scalar. An H×W×C tensor becomes C values (or N×C in batched code). Flatten instead gives HWC values.

Input feature mapFlatten sizeGAP sizeDense-to-10 params with bias
7×7×51225,088512Flatten: 250,890; GAP: 5,130
10×10×646,40064Flatten: 64,010; GAP: 650

GAP greatly reduces classifier parameters and gives a channel-level summary, but loses exact spatial coordinates. The March paper asks what the dimension becomes after GAP and compares dense parameter burden. GAP itself has no trainable parameters.

10. A CNN as a sequence of feature transformations

A common classifier alternates convolution, nonlinearity, and occasional downsampling, then uses a classifier head. Exact architectures vary, but each stage should be shape-traced.

As resolution decreases, later layers can afford more channels. Convolution learns local features; activations add nonlinearity; pooling/stride reduces resolution; the head maps learned representation to task outputs. Residual connections and normalization appear in deeper architectures, but the same shape and parameter reasoning still applies.

Channels are feature types, not RGB colors

After the first convolution, output channels are learned feature maps. They no longer correspond to red, green, and blue. A 64-channel tensor means 64 learned responses per spatial location.

11. PyTorch code patterns the quiz papers use

Conv2d argument order

# nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)
conv = nn.Conv2d(16, 8, kernel_size=3, stride=1, padding=0)
# input: [B, 16, H, W]; output channels: 8

The first number must match the input tensor's channel dimension. The second is number of filters / output channels. This exact distinction is tested in the supplied MCQs.

Calculate a shape by formula or inspect it

x = torch.randn(4, 3, 32, 32)       # NCHW
conv = nn.Conv2d(3, 16, 3, stride=1, padding=1)
pool = nn.MaxPool2d(kernel_size=2, stride=2)
y = pool(torch.relu(conv(x)))
print(y.shape)  # [4, 16, 16, 16]

Conv padding=1 preserves 32×32; pooling halves it to 16×16. ReLU preserves all dimensions.

Parameter count from the module

conv = nn.Conv2d(3, 16, kernel_size=3, bias=True)
count = sum(parameter.numel() for parameter in conv.parameters())
# 3*16*3*3 + 16 = 448

numel() is product of tensor dimensions. In an exam, calculate it by formula; in code, inspect exact registered parameter tensors. Do not count pooling, activation, or padding as weights.

Tensor order and flatten

x = torch.randn(8, 32, 7, 7)        # [N,C,H,W]
x = torch.flatten(x, start_dim=1)    # [N, C*H*W] = [8,1568]
head = nn.Linear(32 * 7 * 7, 10)

Keep batch dimension by flattening from dimension 1. A bare flatten() can collapse batch and feature axes, which is usually wrong for classification.

Concatenate feature branches correctly

# Each branch is [N, channels, H, W], and H,W must agree
out = torch.cat([branch1, branch2, branch3], dim=1)
# output channels = c1 + c2 + c3

In PyTorch NCHW, channel axis is 1. In NHWC, channel axis is usually −1. Concatenation axis is a common shape question.

12. Solved PYQ-style numericals

Question pattern 1: 6×6×2 → max pool → pointwise convolution

Start H×W×C=6×6×2. Pool 2×2, stride 2 gives 3×3×2. A 1×1 conv has four filters; spatial dimensions stay 3×3, channels become 4. Answer: 3×3×4.

Pattern 2: concatenate Inception branches

Branches produce 28×28×64, 28×28×128, 28×28×32, and 28×28×32. H,W align; concatenate C: 64+128+32+32=256. Output: 28×28×256.

Pattern 3: three 3×3 convolutions receptive field

Initialize R=1. Layer 1: R=1+2=3. Layer 2: 3+2=5. Layer 3: 5+2=7. Answer: 7×7.

Pattern 4: SAME padding for odd kernels

Stride 1; preserve size. K=5: P=(5−1)/2=2. K=3: P=1. Both produce same spatial dimension as input.

Pattern 5: resized image and parameter difference

Given one filter K=12×12 spanning 4 channels, with no bias specified: parameters=12×12×4=576. The March Set 1 and Set 2 papers then resize the input image from 12×12×4 to 14×14×4 while keeping the stated filter unchanged. The convolution still has 576 parameters. Additional parameters: 0, matching the answer shown in both papers. Image resolution changes the number of filter placements/output locations, not the learned weights.

Important source reconciliation: the quiz papers mark 0 as the answer: resolution changed, filter did not. The exam master-notes summary has a separate 208 calculation that assumes the filter also grows to 14×14; that assumption is absent from the paper question. In an exam, follow the stated kernel. Only if both input filter sizes are explicitly changed does the count rise to 14×14×4−12×12×4=208.

Pattern 6: Conv2d parameters with bias

Conv1: input channels 3, output filters 16, kernel 3×3: 3×3×3×16+16=448. Conv2: input channels 16, output filters 32, kernel 3×3: 3×3×16×32+32=4,640. Pool layers contribute 0 parameters.

Pattern 7: GAP compared with Flatten

Input 7×7×512. Flatten=25,088 features. GAP=512 features. Dense to 10 with bias: flatten 25,088×10+10=250,890; GAP 512×10+10=5,130. GAP saves 245,760 classifier parameters in this comparison.

Pattern 8: full CNN total parameters

Use the earlier architecture: conv1=448, conv2=4,640, fc1 from 32×8×8=2,048 to 128 gives 262,272, fc2 128→10 gives 1,290. Total=448+4,640+262,272+1,290=268,650. Pooling/activation/flatten add zero.

Pattern 9: compare FC and Conv parameter counts

Grayscale 10×10, five outputs. Dense after flatten with no bias: 100×5=500. Five full-image 10×10 filters, one input channel, no bias: 10×10×1×5=500. Same parameter count in this setup; do not say convolution always has fewer parameters without calculating.

Pattern 10: parameter count vs feature-map resolution

One 3×3 Conv2d, 64 input and 64 output channels, bias enabled has 3×3×64×64+64=36,928 parameters whether input feature map is 16×16 or 32×32. The larger map causes more multiply-accumulate operations, not more shared filter weights.

14. Practice questions with solutions

Q1. Input 28×28×1, Conv 3×3, stride 1, padding 0, 8 filters. Output shape and params with bias?

Shape: 26×26×8. Parameters: 3×3×1×8+8=80.

Q2. Input [B,16,20,20], PyTorch Conv2d(16,32,3,padding=1,stride=2). Output shape?

Each spatial axis floor((20+2−3)/2)+1=floor(19/2)+1=10. Output [B,32,10,10].

Q3. Same layer's parameter count?

3×3×16×32+32=4,640. Stride and padding do not affect learned parameter count.

Q4. Four 3×3 stride-1 conv layers: receptive field side?

1+4(3−1)=9, so 9×9.

Q5. 5×5 stride-1 SAME convolution: padding per side?

P=2 for odd K and stride 1; output spatial size is preserved.

Q6. Pool output [N,24,14,14], then 1×1 Conv with 40 filters. Shape?

[N,40,14,14]. Spatial axes remain; channel depth changes.

Q7. Three branches have [N,32,8,8], [N,48,8,8], [N,16,8,8]. Concatenated shape?

[N,96,8,8], concatenate on NCHW channel dimension 1.

Q8. GAP on [N,128,7,7] produces what shape?

[N,128] (often by averaging H,W while retaining batch and channel).

Q9. Conv input channels 3, output 10, kernel 5×5, bias disabled. Params?

5×5×3×10=750.

Q10. Image width grows from 32 to 64. Same fixed 3×3 Conv has more parameters?

No. Same kernel/channels/bias means same learned parameters; compute/output locations increase.

Q11. Why does three 3×3 convolution stack have 7×7 receptive field?

Start at 1; each stride-1 3×3 adds 2: 1→3→5→7.

Q12. What is wrong with Conv2d(8,16,3) for an input tensor [N,16,H,W]?

First argument says 8 input channels, but tensor has 16. Use Conv2d(16,16,3) if 16 output filters are intended, or another desired out_channels value.

15. Full PyTorch example: train a small CNN

This integrated example defines an MNIST classifier, checks tensor conventions, computes layer shapes and parameter count, trains with a correct update loop, validates, then evaluates. It is placed at the end as a template. It assumes torchvision is installed and downloads MNIST when needed. The code favors clarity over state-of-the-art accuracy.

import torch
from torch import nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

# ------------------------------------------------------------
# 1) Choose device, reproducibility, and image preprocessing
# ------------------------------------------------------------
torch.manual_seed(7)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# MNIST is grayscale 28x28.
# ToTensor converts PIL/uint8 [0,255] to float [0,1], shape [1,28,28].
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,))
])

train_ds = datasets.MNIST(
    root="./data", train=True, download=True, transform=transform
)
test_ds = datasets.MNIST(
    root="./data", train=False, download=True, transform=transform
)

# A validation subset is separated from training data for model selection.
train_ds, val_ds = torch.utils.data.random_split(
    train_ds, [50000, 10000],
    generator=torch.Generator().manual_seed(7)
)
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=128, shuffle=False)
test_loader = DataLoader(test_ds, batch_size=128, shuffle=False)

# ------------------------------------------------------------
# 2) Define a convolutional neural network
# ------------------------------------------------------------
class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(
            in_channels=1, out_channels=16,
            kernel_size=3, stride=1, padding=1
        )
        self.conv2 = nn.Conv2d(
            in_channels=16, out_channels=32,
            kernel_size=3, stride=1, padding=1
        )
        self.pool = nn.MaxPool2d(kernel_size=2, stride=2)
        self.relu = nn.ReLU()

        # 28x28 -> pool -> 14x14 -> pool -> 7x7
        # 32 channels * 7 * 7 = 1568 input features
        self.fc1 = nn.Linear(32 * 7 * 7, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = self.relu(self.conv1(x))  # [N,1,28,28] -> [N,16,28,28]
        x = self.pool(x)              # -> [N,16,14,14]
        x = self.relu(self.conv2(x))  # -> [N,32,14,14]
        x = self.pool(x)              # -> [N,32,7,7]
        x = torch.flatten(x, start_dim=1)  # -> [N,1568]
        x = self.relu(self.fc1(x))    # -> [N,128]
        logits = self.fc2(x)          # -> [N,10]
        return logits                 # raw class scores

model = SmallCNN().to(device)

# Parameter count by layer:
# conv1: 3*3*1*16 + 16 = 160
# conv2: 3*3*16*32 + 32 = 4,640
# fc1: 1568*128 + 128 = 200,832
# fc2: 128*10 + 10 = 1,290
# total = 206,922 trainable parameters
print("trainable parameters:",
      sum(p.numel() for p in model.parameters() if p.requires_grad))

# ------------------------------------------------------------
# 3) Configure objective and optimizer
# ------------------------------------------------------------
# CrossEntropyLoss expects logits [N,10] and integer labels [N].
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# ------------------------------------------------------------
# 4) Train: clear -> forward -> loss -> backward -> step
# ------------------------------------------------------------
for epoch in range(5):
    model.train()
    train_loss_sum = 0.0
    train_correct = 0
    train_count = 0

    for images, labels in train_loader:
        images = images.to(device)  # [N,1,28,28]
        labels = labels.to(device)  # [N], integers 0..9

        optimizer.zero_grad()        # PyTorch gradients accumulate by default
        logits = model(images)       # forward pass
        loss = criterion(logits, labels)
        loss.backward()              # compute gradients for registered params
        optimizer.step()             # update weights and biases

        train_loss_sum += loss.item() * images.size(0)
        train_correct += (logits.argmax(dim=1) == labels).sum().item()
        train_count += labels.size(0)

    train_loss = train_loss_sum / train_count
    train_accuracy = train_correct / train_count

    # --------------------------------------------------------
    # 5) Validate without updating weights
    # --------------------------------------------------------
    model.eval()
    val_loss_sum = 0.0
    val_correct = 0
    val_count = 0

    with torch.no_grad():
        for images, labels in val_loader:
            images = images.to(device)
            labels = labels.to(device)
            logits = model(images)
            loss = criterion(logits, labels)
            val_loss_sum += loss.item() * images.size(0)
            val_correct += (logits.argmax(dim=1) == labels).sum().item()
            val_count += labels.size(0)

    val_loss = val_loss_sum / val_count
    val_accuracy = val_correct / val_count
    print(
        f"epoch {epoch + 1}: "
        f"train loss={train_loss:.4f}, accuracy={train_accuracy:.4f}; "
        f"val loss={val_loss:.4f}, accuracy={val_accuracy:.4f}"
    )

# ------------------------------------------------------------
# 6) Final test evaluation (after choices are finished)
# ------------------------------------------------------------
model.eval()
test_correct, test_count = 0, 0
with torch.no_grad():
    for images, labels in test_loader:
        images, labels = images.to(device), labels.to(device)
        logits = model(images)
        test_correct += (logits.argmax(dim=1) == labels).sum().item()
        test_count += labels.size(0)

print("test accuracy:", test_correct / test_count)

# ------------------------------------------------------------
# 7) Inspect one prediction
# ------------------------------------------------------------
images, labels = next(iter(test_loader))
images = images.to(device)
with torch.no_grad():
    logits = model(images[:1])              # [1,10]
    probabilities = logits.softmax(dim=1)  # for interpretation only
    predicted = logits.argmax(dim=1)

print("true label:", labels[0].item())
print("predicted:", predicted.item())
print("class probabilities:", probabilities.cpu())

Full-code walkthrough

  1. Transforms: ToTensor creates a floating tensor and scales pixels; Normalize standardizes with supplied training-set statistics. The transform is passed to each dataset; merely defining it would not apply it.
  2. Dataset split: validation is carved from training; test is separate. In a formal experiment, maintain class stratification and document the split.
  3. Input format: MNIST batch is NCHW=[N,1,28,28], matching Conv2d in_channels=1.
  4. Conv1: 3×3, padding 1, stride 1 preserves 28×28 and creates 16 channels. ReLU preserves shape.
  5. Pool: 2×2 stride 2 halves each spatial axis: 28→14.
  6. Conv2: expects 16 channels and returns 32; padding 1 keeps 14×14.
  7. Second pool: 14→7. Flatten from dimension 1 retains batch and yields 32×7×7=1,568 features per image.
  8. Classifier: fc1 maps 1,568→128; fc2 maps 128→10 raw logits.
  9. Parameter count: conv1 160 + conv2 4,640 + fc1 200,832 + fc2 1,290 = 206,922. Pool/ReLU/flatten add zero. The fc1 layer dominates this small network.
  10. Loss contract: CrossEntropyLoss receives logits and integer target IDs, no softmax beforehand.
  11. Training order: zero_grad, forward, loss, backward, step. This avoids the gradient accumulation bug explicitly tested in the supplied papers.
  12. Evaluation: model.eval changes Dropout/BatchNorm behavior; no_grad disables gradient tracking. Neither performs an optimizer update.
  13. Prediction: softmax probabilities are for display; argmax logits gives the same class.
Shape audit for this model: [N,1,28,28] → [N,16,28,28] → [N,16,14,14] → [N,32,14,14] → [N,32,7,7] → [N,1568] → [N,128] → [N,10].
