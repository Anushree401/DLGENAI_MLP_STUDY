How to use these notes

This week connects two different meanings of “generate.” An autoencoder reconstructs an input through a compressed representation; a VAE learns a probability distribution in a latent space from which new examples can be sampled; a GAN trains a generator against a discriminator. Keep their objectives, latent spaces, and failure modes distinct.

Exam-pattern note: The supplied Quiz 1 papers focus mainly on early neural-network and CNN material. The supplied exam notes include later-week conceptual prompts such as the LSTM forget gate and the ideal GAN discriminator output D(G(z))=0.5. So the GAN/AE/VAE practice below emphasizes definition traps, a short KL numeric, loss-sign reasoning, shape tracing, and a code update-order question—the same MCQ/numerical/code-reading style used in the papers.

1. Autoencoders: learn to reconstruct

Think of an autoencoder as packing and unpacking. The encoder packs an input into a shorter code; the decoder unpacks that code into a reconstruction. Training compares the reconstruction with the original and adjusts both parts to reduce the difference. A narrow bottleneck forces the code to preserve useful information, but an ordinary autoencoder does not automatically make a smooth space for sampling new examples.

1.1 Encoder, bottleneck, decoder

An encoder z=fφ(x) compresses an input into a latent code; a decoder x̂=gθ(z) attempts to reconstruct it. Train by minimizing a reconstruction loss. For continuous data, MSE corresponds to a Gaussian observation model with fixed variance (up to scale). For binary-valued or appropriately normalized image pixels, binary cross-entropy corresponds to a Bernoulli observation model.

Lrecon(x,x̂) = −log pθ(x|z) (often MSE or BCE under a chosen observation model)

A narrow bottleneck, weight decay, sparsity penalty, denoising corruption, or convolutional structure can encourage useful representations. But a plain deterministic autoencoder does not promise that arbitrary points sampled from a simple distribution decode into realistic examples. Its latent codes may occupy disconnected or irregular regions. Reconstruction is the training task; a well-defined generative prior is a separate modeling choice.

1.2 Variants and uses

  • Denoising AE: corrupt x to x̃ but reconstruct clean x. Learns features robust to chosen corruptions.
  • Sparse AE: penalize activation density, encouraging many code units to be inactive.
  • Convolutional AE: use spatial convolutions in encoder/decoder for image structure.
  • Anomaly detection: train on normal data and flag unusual reconstruction error. This is not automatically reliable: an expressive AE may also reconstruct outliers well.
  • Compression: a learned latent is useful only if representation plus side information/coding cost is favorable.

1.3 Shape/parameter mini-example

A flattened 28×28 image has 784 inputs. An MLP encoder 784→256→2 has (784×256+256)+(256×2+2)=200,960+514=201,474 parameters. If a symmetric decoder 2→256→784 is used, it adds (2×256+256)+(256×784+784)=768+201,488=202,256; total 403,730. The bottleneck width is 2, but parameter count is determined by all weights and biases.

# One deterministic autoencoder pass
z = encoder(x)                  # [B, latent_dim]
x_logits = decoder(z)           # [B, 784]
loss = F.binary_cross_entropy_with_logits(x_logits, x, reduction="sum")

If the decoder ends in sigmoid probabilities, use BCE; if it returns logits, use BCE-with-logits for numerical stability. Do not apply sigmoid and then pass those probabilities to BCE-with-logits.

2. Variational autoencoders (VAEs)

2.1 Latent variable model

A VAE posits a generative model pθ(x,z)=p(z)pθ(x|z), commonly with prior p(z)=N(0,I). Exact posterior inference p(z|x) is often intractable, so an encoder approximates it with qφ(z|x). For a diagonal Gaussian, the encoder returns a mean vector μ(x) and log-variance vector logσ²(x).

qφ(z|x)=N(μ(x), diag(σ²(x)))

The training objective maximizes the evidence lower bound (ELBO): log pθ(x) ≥ Eq[log pθ(x|z)] − KL(qφ(z|x) || p(z)). Equivalently minimize its negative: reconstruction negative log-likelihood plus KL regularization.

LVAE = −Eq(z|x)[log pθ(x|z)] + KL(qφ(z|x) || p(z))

2.2 Reparameterization trick

Why is the reparameterization trick needed? A VAE wants a random hidden code, but a random draw blocks the ordinary learning signal. Instead, it learns a center μ and spread σ, then computes z=μ+σ·ε, where ε is random noise from a fixed simple distribution. The randomness is now isolated in ε, while the model can still adjust μ and σ to improve the result.

Sampling z directly from a distribution whose parameters depend on the encoder would obstruct ordinary backpropagation through that random draw. Instead, sample parameter-free noise ε∼N(0,I) and form z=μ+σ⊙ε. The randomness is isolated in ε; gradients flow through μ and σ. Numerically compute σ=exp(0.5·logσ²), because the network predicts log variance for unconstrained values while variance stays positive.

2.3 KL divergence for a diagonal Gaussian

For q=N(μ,σ²) and p=N(0,1) in one dimension:

KL(q||p)=½(μ²+σ²−1−lnσ²)

For d independent latent dimensions, sum this expression over dimensions. The KL is non-negative and reaches 0 exactly when q=p. In code use log variance directly to avoid taking a log of a tiny variance.

Worked numeric: μ=1 and σ²=0.5. Then ln(0.5)=−0.6931, so KL=0.5[1+0.5−1−(−0.6931)]=0.5×1.1931=0.5966 nats. If μ=0 and σ²=1, KL=0.

For μ=[0,1], logσ²=[0,ln(.5)], sum KL=0+0.5966=0.5966. Mean-over-dim reduction would instead report 0.2983; always notice the reduction convention when comparing numbers.

2.4 β-VAE and posterior collapse

A β-VAE uses L=reconstruction+β·KL. Larger β pushes q(z|x) closer to the prior and can encourage a more regular/disentangled latent representation, but often worsens reconstruction. β is a tradeoff, not a free quality improvement. Posterior collapse occurs when q(z|x) becomes close to p(z) and the decoder largely ignores z; KL becomes near zero while reconstruction may remain decent. Remedies include KL warm-up/annealing, free bits, decoder changes, and careful capacity tuning.

2.5 Sampling and interpolation

After training, draw z~N(0,I) and decode. Sampling from the prior works because training regularized encoded posteriors toward that prior. Interpolate between zA and zB to inspect latent geometry; linear interpolation in a Gaussian latent may pass through low-density regions, so smoothly changing outputs are an empirical property, not a theorem.

3. Generative adversarial networks (GANs)

3.1 The two-player game

Start from zero: how does a GAN learn? The generator is a counterfeiter trying to make convincing samples; the discriminator is a detective trying to tell real samples from fake ones. The detective learns from both kinds, then the counterfeiter improves using the detective’s feedback. They take turns. If the detective becomes too strong too quickly, the generator may receive weak learning signals.

The generator maps noise z∼pz to a synthetic sample G(z). The discriminator returns a score/probability D(x) that an input is real rather than generated. D learns from real examples labeled 1 and generated examples labeled 0; G learns to make generated examples look real to D.

minG maxD V(D,G)=Ex~pdata[log D(x)] + Ez~pz[log(1−D(G(z)))]

In the original minimax form, G minimizes the second term. Early in training D(G(z)) may be near 0, so that loss can saturate and provide weak gradients. The common non-saturating generator loss instead maximizes log D(G(z)), equivalently minimizes −log D(G(z)); it has the same ideal target but often stronger early gradients.

3.2 Optimal discriminator and equilibrium

For fixed generator distribution pg, the optimal discriminator is D*(x)=pdata(x)/(pdata(x)+pg(x)). When distributions match, pg=pdata, D*(x)=1/2 wherever the distributions overlap. Thus at the ideal equilibrium the discriminator cannot tell real from fake and outputs 0.5; 0.5 does not mean the generator is bad.

Likely MCQ trap: At equilibrium, D(G(z))=0.5. If a generator sample is clearly rejected early in training, D(G(z)) near 0 may actually mean D is currently confident the sample is fake, not that the discriminator is “50% correct.” Distinguish D’s probability score from overall classifier accuracy.

3.3 Loss numeric with binary cross entropy

Suppose D(real)=0.8 and D(fake)=0.2. Using mean BCE for one real and one fake example, LD=½[−ln(.8)−ln(1−.2)]=½(0.2231+0.2231)=0.2231. For the non-saturating generator loss on this fake, LG=−ln(.2)=1.609. If D(fake) rises to .8, non-saturating generator loss becomes −ln(.8)=.223. Always note whether a question asks a sum or mean reduction.

3.4 Alternating optimization and detach

  1. D update: score real images; generate fake images; detach them from G’s graph; compute real=1/fake=0 losses; backpropagate and step D.
  2. G update: generate fresh fake images; pass them through D but label them real for the generator objective; backpropagate through D’s operations into G; step G.
  3. Do not update G using D’s real/fake labels directly as if G were a classifier. G wants D(fake) high.
# Discriminator phase
optimizer_D.zero_grad()
loss_D = bce(D(real), ones) + bce(D(G(z).detach()), zeros)
loss_D.backward(); optimizer_D.step()
# Generator phase
optimizer_G.zero_grad()
loss_G = bce(D(G(z)), ones)       # fool D
loss_G.backward(); optimizer_G.step()

For the generator phase, D’s parameters can be temporarily frozen while retaining gradient flow through D to its input; then restore them before its next update. A common bug is accidentally detaching G(z) during the generator phase, which blocks the gradient to G.

3.5 Training difficulties and practical improvements

What is mode collapse? Imagine asking an artist for many different animals but receiving the same cat in every picture. A generator has collapsed when many different random starting points produce nearly identical outputs. Looking at a grid of samples from fixed random seeds helps reveal this; one loss number alone can hide it.
Failure modeWhat it meansPossible response
Mode collapseMany z values map to a few similar outputs; low diversityInspect diversity; adjust D/G balance; minibatch features; alternative objectives
Vanishing G gradientD is too confident and minimax G loss saturatesNon-saturating generator objective; improve balance
Oscillation / instabilityTwo opponents chase a moving targetCareful learning rates, architecture, normalization, update ratio
Overpowerful DD separates train reals from generated fakes too easilyRegularize D; check data and update schedule
MemorizationGenerated outputs resemble training instancesMonitor train/test similarity and nearest neighbors

Wasserstein GANs replace the discriminator probability with a critic score and use a Wasserstein-distance-inspired objective; Lipschitz control (e.g. gradient penalty) is important. Do not call the critic a probability discriminator unless it has been transformed and trained as one.

3.6 Convolutional GANs and conditional generation

DCGAN uses convolutional layers in D and transposed convolutions or upsampling-plus-convolution in G. Common design choices include strided convolutions for downsampling, batch normalization in hidden layers, ReLU in G, LeakyReLU in D, and tanh output when images are scaled to [−1,1]. Labels may be fed to G and D for a conditional GAN. Conditioning enables requested classes but does not guarantee the model follows them.

“VAE samples are always blurry” and “GANs always produce sharper images” are tendencies often seen in simple settings, not universal laws. Quality depends on likelihood, architecture, data, loss, optimization, and metric.

5. Exam-pattern practice with worked solutions

Q1. What does D(G(z)) equal at the ideal GAN equilibrium?

0.5, because pg=pdata and the optimal discriminator has no evidence to distinguish them. It is not 0 or 1.

Q2. For q=N(μ=0, σ²=1) and p=N(0,1), compute KL(q||p).

½(0²+1−1−ln1)=0. Identical distributions have zero KL.

Q3. For q=N(μ=1, σ²=.5), calculate one-dimensional KL to N(0,1).

½(1+.5−1−ln.5)=0.5966 nats.

Q4. In a GAN discriminator update, why use G(z).detach()?

The discriminator update should change discriminator parameters only. Detach blocks this loss’s graph from generator parameters. In the generator update, do not detach: the generator needs the gradient through D back to G.

Q5. A VAE predicts log variance a=−2. What is σ?

σ=exp(a/2)=exp(−1)≈0.3679. Variance=exp(−2)≈0.1353.

Q6. A model returns decoder logits. Which reconstruction loss is coherent with binary pixels?

BCEWithLogitsLoss / binary cross-entropy with logits. Do not sigmoid first and then use a logits-based loss.

6. Complete end-of-week program: train a VAE and a DCGAN

This single MNIST lab trains a compact MLP VAE and a small convolutional GAN side by side. Both use the same images, scaled to [−1,1] for the GAN; the VAE uses [0,1] Bernoulli pixels and decoder logits. It is written for conceptual clarity and a few epochs, not benchmark performance.

"""Week 7 lab: compact MNIST VAE + DCGAN (PyTorch)."""
import torch
from torch import nn
from torch.nn import functional as F
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

SEED = 11
torch.manual_seed(SEED)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
batch_size, latent_dim = 128, 20

# The VAE expects [0,1]; the GAN expects [-1,1]. Keep both explicitly.
mnist = datasets.MNIST(
    root="data", train=True, download=True,
    transform=transforms.ToTensor()
)
loader = DataLoader(mnist, batch_size=batch_size, shuffle=True,
                    drop_last=True, num_workers=0)

# -------------------------- VAE ------------------------------
class VAE(nn.Module):
    def __init__(self, zdim=20):
        super().__init__()
        self.enc1 = nn.Linear(784, 400)
        self.mu = nn.Linear(400, zdim)
        self.logvar = nn.Linear(400, zdim)
        self.dec1 = nn.Linear(zdim, 400)
        self.dec2 = nn.Linear(400, 784)  # logits, no sigmoid here

    def encode(self, x):
        h = F.relu(self.enc1(x.flatten(1)))
        return self.mu(h), self.logvar(h)

    def reparameterize(self, mu, logvar):
        std = torch.exp(0.5 * logvar)
        eps = torch.randn_like(std)
        return mu + std * eps

    def decode(self, z):
        return self.dec2(F.relu(self.dec1(z)))

    def forward(self, x):
        mu, logvar = self.encode(x)
        z = self.reparameterize(mu, logvar)
        return self.decode(z), mu, logvar

def vae_loss(logits, x, mu, logvar):
    # Sum pixels per example and latent dimensions, then average the batch.
    recon = F.binary_cross_entropy_with_logits(
        logits, x.flatten(1), reduction="none"
    ).sum(dim=1)
    kl = -0.5 * (1 + logvar - mu.pow(2) - logvar.exp()).sum(dim=1)
    return (recon + kl).mean(), recon.mean(), kl.mean()

vae = VAE(latent_dim).to(device)
opt_vae = torch.optim.Adam(vae.parameters(), lr=1e-3)

# -------------------------- DCGAN ----------------------------
class Generator(nn.Module):
    def __init__(self, zdim=100):
        super().__init__()
        self.net = nn.Sequential(
            nn.ConvTranspose2d(zdim, 128, 7, 1, 0, bias=False), # 1 -> 7
            nn.BatchNorm2d(128), nn.ReLU(True),
            nn.ConvTranspose2d(128, 64, 4, 2, 1, bias=False),  # 7 -> 14
            nn.BatchNorm2d(64), nn.ReLU(True),
            nn.ConvTranspose2d(64, 1, 4, 2, 1),                # 14 -> 28
            nn.Tanh()
        )
    def forward(self, z):
        return self.net(z)

class Discriminator(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 64, 4, 2, 1), nn.LeakyReLU(0.2, inplace=True),
            nn.Conv2d(64, 128, 4, 2, 1, bias=False),
            nn.BatchNorm2d(128), nn.LeakyReLU(0.2, inplace=True),
            nn.Flatten(), nn.Linear(128 * 7 * 7, 1) # one realness logit
        )
    def forward(self, x):
        return self.net(x)

G, D = Generator().to(device), Discriminator().to(device)
opt_G = torch.optim.Adam(G.parameters(), lr=2e-4, betas=(0.5, 0.999))
opt_D = torch.optim.Adam(D.parameters(), lr=2e-4, betas=(0.5, 0.999))
bce_logits = nn.BCEWithLogitsLoss()
zdim_gan = 100

for epoch in range(3):
    vae.train(); G.train(); D.train()
    vae_total = d_total = g_total = 0.0
    for real01, _ in loader:
        real01 = real01.to(device)                    # [B,1,28,28], [0,1]
        b = real01.size(0)

        # VAE step: x -> (mu,logvar) -> z -> reconstruction logits.
        opt_vae.zero_grad(set_to_none=True)
        recon_logits, mu, logvar = vae(real01)
        loss_vae, recon_part, kl_part = vae_loss(
            recon_logits, real01, mu, logvar
        )
        loss_vae.backward()
        opt_vae.step()
        vae_total += loss_vae.item()

        # GAN input normalization must match G's tanh output [-1,1].
        real = real01 * 2.0 - 1.0
        ones = torch.ones(b, 1, device=device)
        zeros = torch.zeros(b, 1, device=device)

        # 1) Train D: true images -> 1; detached generated images -> 0.
        opt_D.zero_grad(set_to_none=True)
        z = torch.randn(b, zdim_gan, 1, 1, device=device)
        fake = G(z)
        loss_D_real = bce_logits(D(real), ones)
        loss_D_fake = bce_logits(D(fake.detach()), zeros)
        loss_D = loss_D_real + loss_D_fake
        loss_D.backward()
        opt_D.step()

        # 2) Train G: ask D to classify generated images as real.
        # Freeze D weights, but keep the input-gradient path through D.
        opt_G.zero_grad(set_to_none=True)
        for p in D.parameters():
            p.requires_grad_(False)
        z = torch.randn(b, zdim_gan, 1, 1, device=device)
        fake = G(z)
        loss_G = bce_logits(D(fake), ones)
        loss_G.backward()       # gradient passes through D into G
        opt_G.step()
        for p in D.parameters():
            p.requires_grad_(True)
        d_total += loss_D.item(); g_total += loss_G.item()

    print(f"epoch {epoch+1}: VAE={vae_total/len(loader):.2f} "
          f"D={d_total/len(loader):.2f} G={g_total/len(loader):.2f}")

# Generate a small batch from each learned prior.
vae.eval(); G.eval()
with torch.no_grad():
    z = torch.randn(16, latent_dim, device=device)
    vae_images = torch.sigmoid(vae.decode(z)).reshape(16, 1, 28, 28)
    z_gan = torch.randn(16, zdim_gan, 1, 1, device=device)
    gan_images = G(z_gan)                    # already in [-1,1]
print("VAE samples:", vae_images.shape, "range", vae_images.min().item(),
      vae_images.max().item())
print("GAN samples:", gan_images.shape, "range", gan_images.min().item(),
      gan_images.max().item())

Program walkthrough and exam audit

  1. Dataset scales: VAE uses [0,1] pixels as Bernoulli targets; GAN real images are mapped to [−1,1] to match tanh output.
  2. VAE shapes: flatten 784, encoder gives μ/logvar [B,20], sample z [B,20], decoder gives 784 logits per image.
  3. VAE loss: sum 784 reconstruction terms per example and 20 KL terms per example, then average examples. Other valid reductions change reported scale, not the objective’s conceptual parts.
  4. Discriminator step: fake.detach means D training cannot modify G. Real and fake labels are shaped [B,1] to match D’s logits.
  5. Generator step: label generated images as real to D; do not detach fake in this phase.
  6. Architecture shapes: G: [B,100,1,1]→[B,128,7,7]→[B,64,14,14]→[B,1,28,28]; D reverses spatial scale to one logit per image.
  7. Evaluation: inspect sample grids and diversity, not just adversarial losses. GAN loss values alone are not a reliable image-quality score.
Compute note: the code downloads MNIST and trains for three epochs. CPU runtime may be noticeable. Start with a small subset for debugging; for visual quality, train much longer on a GPU and save generated grids at fixed latent seeds.

7. Formula card, traps, and references

VAE sampling

σ=exp(½ logσ²); z=μ+σ⊙ε; ε~N(0,I).

Negative ELBO

Reconstruction NLL + KL(qφ(z|x)||p(z)); β-VAE multiplies KL by β.

Diagonal Gaussian KL

½Σ(μ²+σ²−1−logσ²), against N(0,I).

GAN equilibrium

When pg=pdata, optimal D(x)=½. For non-saturating G, minimize −logD(G(z)).

  • AE reconstruction alone does not guarantee a sampleable latent prior.
  • In VAE code, logvar is not variance; exponentiate it.
  • KL is nonnegative; identical q and p give zero.
  • Generator fake target is real; discriminator fake target is fake.
  • Detach only the fake branch during discriminator learning, not generator learning.
  • Do not report GAN equilibrium from generator loss alone; compare distributions and D behavior.
