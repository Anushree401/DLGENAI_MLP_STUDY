How to use these notes

Week 2 moves from Week 1's equations to working code: build a small neural network in TensorFlow/Keras, train it, and experiment with activations and optimization methods. The goal is to understand the whole path from examples to parameter updates, not just memorize API calls.

Important exam connection: the supplied Quiz 1 papers mainly show PyTorch snippets even though Week 2's course outline names TensorFlow/Keras. They ask what code prints, whether a weight will update, why gradients accumulate, and how to find code bugs. This guide teaches the Keras workflow and explicitly translates the same concepts to PyTorch exam patterns.

Follow the guide in this order: set up data and splits; verify shapes/labels; define the model; compile with a task-appropriate loss and optimizer; fit using training data and validation data; evaluate once on held-out test data. Then change one experimental factor at a time.

Scope boundary: Week 2 is simple feed-forward neural networks and experiments with activations/optimizers. CNN architecture, image-specific model design, and sequence models are later weeks. A short FashionMNIST transform note appears only because the quiz papers use it as a code-reading example.

1. End-to-end supervised learning workflow

A training program is a pipeline with contracts between stages. A correct model with a broken label pipeline or mismatched loss can still fail completely.

Train, validation, and test are different roles

SplitUsed forMay update weights?May guide choices?
TrainingCompute loss and optimize parametersYesYes, via training objective
ValidationCompare epochs/configurations; early stoppingNoYes
TestFinal estimate of generalizationNoNo repeated tuning

For independent examples, a randomized split is common. For time series, split chronologically. If several rows come from the same person, machine, or source, split by group so near-duplicates do not leak across splits. Fit preprocessing statistics only using training data, then apply those learned statistics to validation and test.

Epochs, batches, steps, and updates

Start from zero: what is a batch? Imagine practising with a stack of 100 flashcards. A batch is the handful you check together; after that handful, the model may update its numbers once. An epoch is one complete pass through all 100 cards. So 100 examples with batch size 20 means 5 batches—and usually 5 optimizer updates—in one epoch.
  • Example: one input-target pair.
  • Batch/minibatch: a subset used to estimate gradient in one update.
  • Step: one optimizer update, usually one batch.
  • Epoch: one pass through the training examples.
  • For N training examples and batch size B, batches per epoch are approximately ceil(N/B) when the last smaller batch is retained.

Batch size changes the cost/noise of a gradient estimate. Epoch count is not the same as update count: 10 epochs over 1000 samples with batch size 100 gives about 100 updates.

2. Keras mental model: layers, model, compile, fit

Think of Keras as a cooking recipe. Layers are the steps, and the model connects the steps into one recipe. compile chooses what counts as a mistake and how to adjust the model; fit repeatedly shows training examples and makes those adjustments. evaluate checks examples without teaching, while predict asks for answers.

Keras separates model definition from training configuration and training execution:

model = architecture → model.compile(...) → model.fit(...) → evaluate / predict
  • Layer defines a transformation; Dense computes an affine map and optional activation.
  • Model composes layers and owns trainable variables.
  • compile selects loss, optimizer, and metrics.
  • fit runs training epochs and optionally validates.
  • evaluate computes loss/metrics without optimizer updates.
  • predict computes outputs, not necessarily class decisions.

Sequential or Functional?

Sequential is suitable when layers form one straight chain. The Functional API represents branching, shared layers, multiple inputs/outputs, and skip connections. In this week, Sequential is sufficient for a compact MLP; learning both APIs clarifies that a network is a computation graph.

Keras Dense shape and parameters

Given an input of shape [batch, d], Dense(u) returns [batch,u]. A Dense layer with bias has d×u+u trainable parameters. The batch dimension does not affect the count. Keras often builds variables lazily on first call unless an input shape is supplied.

import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

model = keras.Sequential([
    keras.Input(shape=(20,)),
    layers.Dense(32, activation="relu"),
    layers.Dense(3)  # three raw class scores (logits)
])
model.summary()

The model has 20×32+32=672 parameters in the first layer and 32×3+3=99 in the second; total=771. Input(shape=(20,)) describes one example's features only; batch size is omitted.

3. Data, labels, batching, and preprocessing

Inspect before fitting

  1. Check sample count and feature shape.
  2. Check data type and numeric range (e.g. uint8 0–255 vs float 0–1).
  3. Check label encoding and class counts.
  4. Check missing values, duplicates, and split leakage.
  5. Confirm the model input shape agrees with one example, not the entire dataset shape.

For tabular data, scaling continuous features often helps optimization. For image data, conversion and normalization are common. For labels, integer IDs and one-hot vectors are not interchangeable unless the loss expects that format.

Normalization

standardize feature j: x′ⱼ=(xⱼ−μⱼ)/σⱼ

Compute μ and σ on training data only. A constant feature with σ=0 requires safe handling. For images, dividing uint8 pixels by 255 maps [0,255] to [0,1]; normalization may then center/scale each channel. The transformation's order matters: convert to tensor/float before numeric normalization.

What transforms do in the supplied quiz example

The March papers include code that defines transforms.Compose([ToTensor(), Normalize(...)]) but constructs FashionMNIST without passing the transform argument. The transform object being defined does not automatically modify data. It must be attached in the dataset constructor, e.g. FashionMNIST(..., transform=transform). Otherwise the dataset returns its untransformed image representation.

transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.2860,), (0.3530,))
])
train_ds = FashionMNIST(
    root="./data", train=True, download=True,
    transform=transform  # this attachment is essential
)

This transform issue is an image-pipeline example, not a core Week 2 Keras API requirement. The general code-reading lesson applies everywhere: defining a function/object does not apply it unless the data path calls it.

4. Tensor shapes, targets, and code-reading habits

Shape is a contract between dataset and model. For an MLP, flatten structured input into a feature vector only if the architecture expects it. Common shapes include:

ObjectTypical shapeExample
Batch features[B, d]32 examples with 20 features: [32,20]
Binary labels[B] or [B,1]one 0/1 per example
Multiclass logits[B,C]batch × number of classes
Multiclass IDs[B]integer class for each row
One-hot labels[B,C]one active class coordinate

Label encoding must match the loss

Keras sparse_categorical_crossentropy typically uses integer class IDs; categorical_crossentropy uses one-hot labels. With logits, specify from_logits=True. For a binary task, a one-unit sigmoid output pairs naturally with binary cross-entropy; a one-unit raw logit pairs with a logits-aware BCE. Do not accidentally use C-way softmax labels as a binary target.

Tensor operation questions in PyTorch

Three operations often appear in the provided papers and exam notes:

  • numel() gives product of all shape dimensions; memory in bytes = numel × element_size.
  • stack creates a new dimension; cat extends an existing dimension.
  • squeeze(dim) removes only that dimension if its size is 1; squeeze() removes all size-1 dimensions.
x = torch.randn(1, 5, 1, 3, 1)
x.squeeze(0).shape  # [5, 1, 3, 1]
x.squeeze().shape   # [5, 3]

a = torch.ones(3, 4)
b = torch.zeros(3, 4)
torch.stack([a, b], dim=1).shape  # [3, 2, 4]
torch.cat([a, b], dim=1).shape    # [3, 8]

In an exam, simulate the shape after each call. Do not rely on appearance or guesswork. The papers ask exact output shapes/values and reward precise API semantics.

5. Build a simple network

Choose output according to task

TaskOutput layerInterpretation
Regression y∈ℝone linear output (often no activation)predicted continuous value
Binary classificationone sigmoid probability or one raw logitprobability of positive class
One of C classesC logits (or softmax probabilities)class score distribution
Multilabel C labelsC independent sigmoid probabilities/logitseach label can be independently true

Hidden activations provide nonlinearity. ReLU is common; tanh or sigmoid may be used for particular reasons. A final softmax is optional in Keras depending on loss configuration: either the model outputs probabilities and loss expects probabilities, or model outputs logits and loss is configured with from_logits=True. Do not mix the two contracts.

Keras activation choices

# Hidden ReLU layers, output raw logits
model = keras.Sequential([
    keras.Input(shape=(d_in,)),
    layers.Dense(64, activation="relu"),
    layers.Dense(32, activation="relu"),
    layers.Dense(num_classes)
])

It is often better to output logits for numerical stability. If the final layer includes activation="softmax", compile with a probability-based cross-entropy configuration (from_logits=False). If no softmax is in the model, compile with from_logits=True.

Model capacity and parameter count

More hidden units increase capacity and parameter count. For widths d→h₁→h₂→C, dense parameters are (d h₁+h₁)+(h₁h₂+h₂)+(h₂C+C). More capacity can fit complex patterns but may overfit or cost more. Use validation performance, not training accuracy alone, to select it.

6. Compile: choose objective, metrics, optimizer

Loss = what parameter updates try to reduce

  • Regression: Mean Squared Error or Mean Absolute Error.
  • Binary: binary cross-entropy.
  • Multiclass integer labels: sparse categorical cross-entropy.
  • Multiclass one-hot labels: categorical cross-entropy.

The model's output convention, label encoding, and loss parameters must agree. If the model outputs raw logits, set from_logits=True in the corresponding Keras loss. A mismatch may produce poor learning without an obvious exception.

Metrics = what we monitor

Metrics such as accuracy do not automatically become the training objective. Use accuracy for a quick classification summary, but monitor precision/recall for imbalanced or asymmetric-cost tasks. For regression, MAE and RMSE are interpretable in target units. Validation metrics help detect overfitting.

Optimizer = how parameters are moved

Optimizer combines gradients with a rule and internal state. Learning rate is a hyperparameter. Keras Adam has sensible common defaults, but it is not always best. SGD can generalize well and is instructive for experiments; momentum accelerates consistent directions.

model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
    metrics=[keras.metrics.SparseCategoricalAccuracy(name="accuracy")]
)

Compile does not fit or change weights. It configures what the model will do when training is run. Keras builds/collects trainable variables as the model is built, and fit uses gradients to update them.

7. Fit, evaluate, predict: what happens in each phase

Training step conceptual flow

Correct train loop order

  1. Get batch features and labels.
  2. Clear old gradients (PyTorch explicitly; Keras manages its loop internally).
  3. Compute predictions (forward pass).
  4. Compute scalar loss.
  5. Differentiate loss with respect to trainable parameters.
  6. Apply optimizer update.
zero gradients → forward → loss → backward → optimizer step

In Keras, fit performs these steps under the hood. In a custom PyTorch loop you must write them. Gradients accumulate by default in PyTorch: leaving out zero_grad() makes subsequent backward() add to existing gradients.

Validation is not training

During validation, compute loss/metrics but do not update weights. Keras validation_data=(x_val,y_val) handles this separation during fit. At evaluation, use test data only after choices are complete.

Callbacks

  • EarlyStopping: stop when monitored validation metric stops improving; restore_best_weights=True restores best epoch.
  • ModelCheckpoint: save best model based on validation monitor.
  • ReduceLROnPlateau: lower learning rate when validation metric plateaus.
  • Callbacks do not fix poor data, wrong loss, or train/validation leakage. Check the monitored metric and mode (min/max).

8. Optimizers: SGD, momentum, RMSprop, Adam

Start from zero: what does an optimizer do? A gradient tells the model which direction is downhill, but an optimizer decides how big and how steady each step should be. Plain SGD takes a step based on the current batch. Momentum is like a ball rolling downhill: it remembers recent directions. Adam also tracks recent gradient size, so each parameter can get a more suitable step.

All common first-order optimizers use gradient information but differ in how they smooth and scale it. For minimization, a positive gradient should move the parameter downward.

MethodIdeaStrengthsRisks / knobs
SGDθ←θ−ηgSimple, transparent, low state memory.Learning-rate-sensitive; noisy updates.
Momentum SGDAccumulate moving direction.Accelerates consistent gradients; dampens zigzag.Learning rate and momentum interact.
RMSpropScale each coordinate using recent squared gradients.Adaptive per-parameter step scale.Decay/learning rate still need choices.
AdamMomentum-like first moment + adaptive second moment, bias corrected.Often effective default, quick early progress.Not universally best; state and learning-rate sensitivity.
AdamWAdam with decoupled weight decay.Clearer weight-decay behavior for modern nets.Weight decay is another tuning parameter.

SGD numerical step

Let L(w)=(w−3)². Gradient is 2(w−3). At w=0, g=−6. With learning rate η=.1:

w₁ = 0 − .1(−6) = .6

Loss falls from 9 to (−2.4)²=5.76. A negative gradient leads to an increase in w because subtracting a negative number increases it.

Momentum

vₜ=βvₜ₋₁+gₜ ; θₜ=θₜ₋₁−ηvₜ

Some definitions multiply the new gradient by (1−β), or use a different velocity convention; use the equation provided in the question. With v₀=0, β=.9, current gradient g=−6, η=.1: v₁=−6 and w₁=.6 in the unscaled convention. Momentum retains part of previous direction at later steps.

RMSprop

sₜ=ρsₜ₋₁+(1−ρ)gₜ² ; θₜ=θₜ₋₁−ηgₜ/(√sₜ+ε)

Large recent gradients increase s, scaling their effective update down. Smaller coordinates can receive relatively larger steps.

Adam

mₜ=β₁mₜ₋₁+(1−β₁)gₜ ; vₜ=β₂vₜ₋₁+(1−β₂)gₜ²
m̂ₜ=mₜ/(1−β₁ᵗ), v̂ₜ=vₜ/(1−β₂ᵗ); θₜ=θₜ₋₁−ηm̂ₜ/(√v̂ₜ+ε)

m tracks a smoothed direction; v tracks squared-gradient scale. Bias correction compensates for zero-initialized moment estimates early in training. Common defaults are β₁=.9, β₂=.999, ε≈10⁻⁸. Adam is often a good first experiment, not a guarantee of the best final validation performance.

Adam first-step numerical

Use g₁=−6, m₀=v₀=0, β₁=.9, β₂=.999, η=.1, ε≈0. First, m₁=(1−.9)(−6)=−.6 and v₁=(1−.999)(36)=.036. Bias correction gives m̂₁=−.6/(1−.9)=−6 and v̂₁=.036/(1−.999)=36. The update is θ₁=θ₀−.1(−6)/(√36)=θ₀+.1. For θ₀=0, θ₁≈.1. The small ε changes this only slightly. Contrast plain SGD on the same gradient, whose step magnitude is .6: Adam normalizes by the estimated gradient scale.

9. Experimentation: compare activations and optimizers fairly

An experiment should isolate a question. If optimizer, learning rate, architecture, seed, and batch size all change together, you cannot tell what caused a difference.

Controlled comparison recipe

  1. Write one hypothesis: e.g. “Adam reaches lower training loss than SGD after 20 epochs at this setup.”
  2. Choose a fixed train/validation split and preprocessing.
  3. Use the same architecture and initialization protocol.
  4. Change one factor (optimizer or activation) while holding others fixed.
  5. Repeat with several random seeds when results are noisy.
  6. Compare validation curves, final metric, training speed, and variability.
  7. Choose settings from validation results; use test set once for final report.

Activation experiment

Compare ReLU, tanh, and sigmoid in hidden layers while keeping output/loss matched to the task. ReLU may train efficiently but has inactive units. Tanh is centered but saturates. Sigmoid saturates strongly and can slow deep hidden-layer learning. Do not change the output activation when comparing hidden activations unless that is the explicit question.

Optimizer experiment

Compare SGD, SGD+momentum, and Adam with documented learning rates. Equal numeric learning rates do not always imply equally suitable settings across optimizers. Track train and validation loss by epoch, time per epoch, and a relevant task metric.

Reproducibility and randomness

Set random seeds where supported, record package/runtime versions, data split, architecture, preprocessing, batch size, epoch count, and optimizer settings. GPU kernels and nondeterministic operations may still cause small differences. A seed makes a run more repeatable, not scientifically conclusive.

Regularization/early stopping knobs

Think of overfitting like memorizing practice answers. A student who memorizes only the practice sheet may fail a new question. Regularization makes memorizing harder; early stopping ends practice when performance on separate check-up examples stops improving. Those check-up examples guide when to stop, so they must not be used as the final unbiased test.
  • Dropout randomly masks activations during training; it is disabled in evaluation mode.
  • Weight decay discourages large weights; it changes optimization and should be tuned.
  • Early stopping chooses a checkpoint based on validation behavior.
  • Data augmentation can improve robustness only if transformations preserve labels.

These are experimental factors. Add them only with a reason; a complicated training recipe can hide basic errors.

Overfit one minibatch: a debugging test

Temporarily train on a very small fixed batch and see whether the model can drive training loss low. If it cannot, the issue is likely in the model/loss/labels/update pipeline rather than generalization. This is not a valid performance result; it is a diagnostic.

Gradient checks

In PyTorch inspect whether trainable parameters have gradients and whether values change after optimizer.step. A gradient can exist on a tensor that the optimizer does not own. In Keras inspect model.trainable_variables and ensure the layer was called/built. Also ensure training is not wrapped in no-gradient context or using an incorrect trainable flag.

11. Question-paper code patterns: what to recognize

The supplied exam master notes rank tensor operations and training-loop bugs among frequent Quiz 1 areas. The papers ask exact code output and model behavior, so reason about registration, gradient accumulation, and API semantics—not just the neural-net concept.

Pattern A: will this weight be updated?

For an optimizer to update a value, three things must line up: the value participates in a differentiable computation; it receives a gradient; and the optimizer has been given that parameter. In PyTorch, nn.Parameter assigned as a module attribute is registered automatically.

DefinitionAutograd gradient?In model.parameters()?Optimizer updates it?
self.W=nn.Parameter(torch.randn(...))YesYesYes, if optimizer receives model.parameters()
self.W=torch.randn(..., requires_grad=True)YesNo, not automaticallyNo, unless explicitly passed to optimizer
self.W=torch.randn(...)Usually noNoNo
Weight is used under no_grad/detachedNo path gradientMay be registeredNo useful update for that path

Keras equivalent: layers such as Dense own trainable variables; the model's training machinery sees them. If a custom layer creates a raw TensorFlow variable improperly or marks a variable non-trainable, it may not be trained as intended. Use self.add_weight(..., trainable=True) inside a custom Keras Layer.

Pattern B: missing zero_grad

for xb, yb in loader:
    optimizer.zero_grad()  # reset previous batch gradient
    prediction = model(xb)
    loss = loss_fn(prediction, yb)
    loss.backward()
    optimizer.step()

If zero_grad is omitted, PyTorch adds each new gradient to the existing .grad. Gradients accumulate across batches/epochs and produce unintended updates. The March papers explicitly ask this. In standard Keras fit, its built-in loop handles gradient management; when writing a custom GradientTape loop, you explicitly compute gradients and apply them with optimizer.

Pattern C: zero_grad in wrong place

Clearing after backward but before step discards the gradient and prevents expected update. Clearing once per epoch instead of once per batch makes batches accumulate. Correct order is clear, forward, loss, backward, step for each batch.

Pattern D: parameter gradient vs optimizer update

loss.backward() populates gradients; optimizer.step() changes parameter values. model.train() enables training behavior for Dropout/BatchNorm; it does not itself update parameters. model.eval() switches inference behavior; it is not required for SGD updates and should not replace train mode.

Pattern E: transforms are not applied by being defined

The transform must be passed to a Dataset's transform= argument. Compose is generally invoked as each sample is retrieved; it is not an eager rewrite of the entire dataset when declared.

Pattern F: exact tensor shape/output

Track dimensions after each operation. stack adds one dimension; cat concatenates along existing dimension. squeeze(dim) removes only a size-1 dimension at that index. These are short code-reading questions: avoid interpreting intent and calculate the actual result.

12. Worked numericals for Week 2 practice

Numerical 1: Dense parameter count

Input width 20 → Dense(32) → Dense(3), biases enabled. First layer: 20×32+32=672. Second: 32×3+3=99. Total=771 parameters. For batch size 128, total parameters remains 771.

Numerical 2: batches and optimizer steps

N=1,000 training examples, B=128, drop_remainder=False. Batches=ceil(1000/128)=8; sizes are seven batches of 128 and one of 104. With 5 epochs, optimizer updates=40. If final partial batch is dropped, batches=7 and updates=35 per five epochs.

Numerical 3: one SGD update

Let L(w)=(w−3)², w₀=0, learning rate .1. Gradient g₀=2(0−3)=−6. Update w₁=0−.1(−6)=.6. Loss drops from 9 to 5.76.

Numerical 4: second SGD update

At w₁=.6, g₁=2(.6−3)=−4.8. Another .1 step gives w₂=.6−.1(−4.8)=1.08. The parameter approaches 3. A smaller learning rate would approach more slowly; a much larger value could overshoot.

Numerical 5: first momentum update

Use vₜ=βvₜ₋₁+gₜ with v₀=0, β=.9 and g₀=−6. Then v₁=−6. With η=.1, w₁=.6. On later steps, velocity includes history. Some texts define v with (1−β)g; use the exact equation specified.

Numerical 6: cross-entropy from probabilities

Three-class correct label is class 2, predicted probabilities [.1,.7,.2]. Cross-entropy is −ln(.7)=.357. If labels are class ID 1 under zero indexing, it is the middle coordinate.

Numerical 7: accuracy and F1

TP=18,FN=2,FP=10,TN=70. Accuracy=(18+70)/100=.88. Precision=18/28=.643. Recall=18/20=.90. F1=2(.643)(.90)/(.643+.90)≈.75.

Numerical 8: tensor element count/memory

Tensor shape [4,3,2] has 4×3×2=24 elements. float32 has 4 bytes each, so storage for values is 24×4=96 bytes (ignoring metadata, gradients, optimizer state, and allocator overhead).

13. Small code patterns between topics

Model summary and parameter check

model = keras.Sequential([
    keras.Input(shape=(20,)),
    layers.Dense(32, activation="relu"),
    layers.Dense(3)
])
model.summary()
print(model.count_params())  # 771

Validation and callbacks

early_stop = keras.callbacks.EarlyStopping(
    monitor="val_loss", patience=3, restore_best_weights=True
)
history = model.fit(
    x_train, y_train,
    validation_data=(x_val, y_val),
    epochs=50, batch_size=32,
    callbacks=[early_stop]
)

history.history stores epoch metrics such as loss, accuracy, val_loss, and val_accuracy. A callback monitors the value; the validation set is not used for gradient updates.

Explicit activation/optimizer experiment

def make_model(activation="relu"):
    return keras.Sequential([
        keras.Input(shape=(d_in,)),
        layers.Dense(64, activation=activation),
        layers.Dense(num_classes)  # logits
    ])

for name, optimizer in [
    ("sgd", keras.optimizers.SGD(learning_rate=0.05)),
    ("momentum", keras.optimizers.SGD(
        learning_rate=0.05, momentum=0.9
    )),
    ("adam", keras.optimizers.Adam(learning_rate=1e-3))
]:
    # Keep the split, architecture, and epoch budget controlled.
    model = make_model("relu")
    model.compile(
        optimizer=optimizer,
        loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
        metrics=["accuracy"]
    )
    history = model.fit(
        x_train, y_train, validation_data=(x_val, y_val),
        epochs=20, batch_size=32, verbose=0
    )
    print(name, min(history.history["val_loss"]))

This is a comparison pattern, not a promise that each optimizer should use an identical learning rate. For a scientifically fair comparison, document settings and consider tuning each optimizer fairly on the validation set.

15. Practice questions with solutions

Q1. Dataset has N=900 and batch size 100. How many optimizer updates per epoch?

9 if all examples are kept. If batch size does not divide N, use ceil unless the final partial batch is dropped.

Q2. Dense(10) receives 6 features. Count parameters with bias.

6×10+10=70.

Q3. A model outputs 4 raw logits and y is an integer class ID. Which Keras loss configuration?

SparseCategoricalCrossentropy(from_logits=True).

Q4. What happens if PyTorch training omits zero_grad each batch?

Gradients accumulate in .grad across backward calls, so updates use summed/stale gradients rather than only the current batch's intended gradient.

Q5. A tensor has shape [1,5,1,3,1]. Find squeeze(0) and squeeze() shapes.

squeeze(0) → [5,1,3,1]. squeeze() → [5,3].

Q6. Why can requires_grad=True still fail to make a custom PyTorch weight update?

Autograd may calculate its gradient, but if it is a plain tensor not registered as nn.Parameter and not explicitly passed to optimizer, optimizer will not update it.

Q7. For L(w)=(w−3)², w=0, η=.1, perform one SGD step.

Gradient=−6. New w=0.6.

Q8. Training accuracy rises, validation loss rises. What is the likely issue and one remedy?

Overfitting. Try early stopping, more appropriate data augmentation, regularization, more data, or a smaller model; check split quality.

Q9. In Keras, what is the difference between compile and fit?

compile configures optimizer, loss, metrics. fit executes training across batches/epochs and updates weights.

Q10. Defined a transform Compose but omitted transform= when constructing dataset. Are transforms applied?

No. Defining the pipeline alone does not attach it to dataset access.

Q11. Why is test accuracy not used to choose between optimizers?

Repeated selection based on test results leaks information and biases the final estimate. Use validation for choices; test once at the end.

Q12. Explain zero_grad → forward → loss → backward → step.

Clear old gradients; calculate predictions; score predictions; differentiate loss; update parameters with optimizer.

14. Full Keras example: classify a tabular dataset

This example generates a small synthetic three-class dataset, creates train/validation/test splits, standardizes using training statistics only, then trains and evaluates a Keras MLP. It assumes NumPy and TensorFlow are installed. The comments explain each data contract and stage.

import numpy as np
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

# Reproducibility: useful for debugging and comparisons.
tf.keras.utils.set_random_seed(7)

# ------------------------------------------------------------
# Generate a small, fully runnable three-class dataset.
# Each class is a cluster around a different 4-D center.
# ------------------------------------------------------------
rng = np.random.default_rng(7)
centers = np.array([
    [-2.0, 0.0, 0.0, 0.0],
    [ 2.0, 0.0, 0.0, 0.0],
    [ 0.0, 2.0, 0.0, 0.0],
], dtype=np.float32)
examples_per_class = 300
x_all = np.vstack([
    rng.normal(loc=center, scale=0.8, size=(examples_per_class, 4))
    for center in centers
]).astype(np.float32)
y_all = np.repeat(np.arange(3, dtype=np.int32), examples_per_class)
order = rng.permutation(len(y_all))
x_all, y_all = x_all[order], y_all[order]

# Split before fitting preprocessing statistics.
x_train, x_val, x_test = x_all[:600], x_all[600:750], x_all[750:]
y_train, y_val, y_test = y_all[:600], y_all[600:750], y_all[750:]
mean = x_train.mean(axis=0, keepdims=True)
std = x_train.std(axis=0, keepdims=True)
std = np.where(std == 0, 1.0, std)
x_train = (x_train - mean) / std
x_val = (x_val - mean) / std
x_test = (x_test - mean) / std

# ------------------------------------------------------------
# Expected data contracts:
#   x_train: float array [N_train, d_in]
#   y_train: integer array [N_train], values in 0..C-1
#   x_val, y_val: same feature/label convention
#   x_test, y_test: held out until model choices are finished
# ------------------------------------------------------------
num_features = x_train.shape[1]
num_classes = int(np.max(y_train)) + 1

# ------------------------------------------------------------
# Build a feed-forward MLP.
# Dense parameter counts:
#   first layer: d_in*64 + 64
#   second layer: 64*32 + 32
#   output: 32*C + C
# ------------------------------------------------------------
model = keras.Sequential([
    keras.Input(shape=(num_features,)),
    layers.Dense(64, activation="relu", name="hidden_1"),
    layers.Dense(32, activation="relu", name="hidden_2"),
    layers.Dense(num_classes, name="class_logits")
])

# ------------------------------------------------------------
# Configure training.
# The final layer emits logits, so from_logits=True.
# y values are integer IDs, so use sparse categorical CE.
# ------------------------------------------------------------
model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
    metrics=[
        keras.metrics.SparseCategoricalAccuracy(name="accuracy")
    ]
)

model.summary()

# Save the best validation checkpoint and stop if it stops improving.
callbacks = [
    keras.callbacks.ModelCheckpoint(
        "best_week2_model.keras",
        monitor="val_loss",
        save_best_only=True
    ),
    keras.callbacks.EarlyStopping(
        monitor="val_loss",
        patience=5,
        restore_best_weights=True
    )
]

# Training updates weights using x_train/y_train.
# Validation computes metrics but does not update the weights.
history = model.fit(
    x_train, y_train,
    validation_data=(x_val, y_val),
    epochs=50,
    batch_size=32,
    shuffle=True,
    callbacks=callbacks,
    verbose=1
)

# Test data is reserved for this final assessment.
test_loss, test_accuracy = model.evaluate(
    x_test, y_test, verbose=0
)
print("test loss:", test_loss)
print("test accuracy:", test_accuracy)

# Predict gives logits because the last Dense has no softmax.
test_logits = model.predict(x_test[:5], verbose=0)
test_probabilities = tf.nn.softmax(test_logits, axis=1)
test_classes = tf.argmax(test_logits, axis=1)

print("logits for five examples:", test_logits)
print("probabilities:", test_probabilities.numpy())
print("predicted class IDs:", test_classes.numpy())

Read the full program line by line

  1. Seed: seeds random initializers and framework RNGs to make debugging runs more reproducible.
  2. Data shapes: each row is one example. Input dimension is the second axis; y contains one integer ID per row.
  3. Class count: this max+1 shortcut assumes labels are contiguous and start at zero. For noncontiguous labels, define a mapping explicitly.
  4. Architecture: hidden Dense layers use ReLU; output Dense returns C logits. No softmax is required in the model when loss uses from_logits=True.
  5. Parameter count: first layer d×64+64; next 64×32+32; output 32×C+C.
  6. Compile: Adam is the optimizer, sparse categorical cross-entropy is the objective, accuracy is a reported metric.
  7. Fit: minibatch updates use training examples. Validation is evaluated by epoch and does not update weights.
  8. Checkpoint/early stopping: save best val_loss and stop after five unimproved epochs; restore the best weights.
  9. Test: evaluate after the decisions are finished. Repeatedly tuning on test data turns it into validation data.
  10. Inference: predict returns logits. Softmax converts them to probabilities; argmax returns class IDs.
Output/loss consistency: raw logits + SparseCategoricalCrossentropy(from_logits=True) + integer labels. If instead the final Dense uses softmax, configure loss for probabilities (from_logits=False). Never mix these contracts.

TensorFlow custom training loop, conceptually

Keras fit owns its training loop. For custom logic, GradientTape records operations, gradient computes d(loss)/d(variable), and optimizer.apply_gradients updates trainable variables:

with tf.GradientTape() as tape:
    logits = model(xb, training=True)
    loss = loss_fn(yb, logits)

grads = tape.gradient(loss, model.trainable_variables)
optimizer.apply_gradients(zip(grads, model.trainable_variables))

This corresponds conceptually to PyTorch's forward → loss → backward → step. Frameworks differ in API and gradient management; the mathematical steps are the same.
